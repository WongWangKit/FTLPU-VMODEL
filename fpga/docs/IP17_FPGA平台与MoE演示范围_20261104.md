**推荐排序的决定性理由：**

1. **HTG-960 优先**：当前主要压力是大量浮点控制/规格化和 MEM/SRF 选择网络占用 LUT，4.09M LUT 比 HBM 更直接。标配 8 GB DDR 已可容纳约 1.33 GiB 量化模型和工作区，暂不需要为了容量扩满 64 GB。
2. **V80 为带宽优先的条件候选**：适合后续权重流式推理和 DSP 密集后端，但不能把 UltraScale+ 的综合数直接视为 Versal 实测。当前 AVED 文档要求 Vivado 2025.1，并列出 Ubuntu 24.04 / RHEL 9.4；本机 2023.2 列出器件不等于具备这一整套生产开发环境。[AVED 官方流程](https://xilinx.github.io/AVED/latest/index.html)
3. **HTG-840-2 为 PCIe/成熟流程候选**：同类 RTL 迁移成本相对低，但仍须按 VU440 重新综合。只有完整设计加 shell 在 LUT/DSP 预算内才启用，不因价格便宜而牺牲 LPU16 配置。

以前的 **VCU118** 仍适合单模块/局部原型，不作为本轮全 LPU16 主推。**U250** 可复用已有板，但不再推荐新购主平台：官方 XCN24001 列出的相关 SKU 已于 2024 年停止接单/出货，产品支持页面存在不代表仍适合新采购。[AMD 生命周期通知](https://docs.amd.com/api/khub/documents/uvPu4FvjY5od_0U~SPDnGA/content)

## 4. 演示模型与算子边界

### 4.2 精度与量化合同

- Q/K/V/O 和 expert gate/up/down：**INT8 对称、zero point=0，每物理 8×8 weight cell 一个 BF16 scale**。`s=BF16(max(abs(W))/127)`；全零块取 s=1；`q=clip(RNE(W/s),−127,127)`。
- 反量化 `BF16(q×s)` 后进入 BF16 乘法，FP32 累加；激活、KV 为 BF16。与当前 MXM cell 级 scale 形式对齐，**不是** per-output-channel AWQ/GPTQ。
- router、norm 权重、embedding/共享 LM head 保留 BF16，优先避免路由和输出层量化误差。router 线性结果按参考 dtype 处理，再转 FP32 进行 TopK/softmax。
- W8 的第一收益是权重存储与传输压缩，**不能据此宣称有 INT8 MAC 吞吐加速**；当前实现会反量化到 BF16。
- bring-up 先 Direct16 BF16 建立数值基线，再启用 W8；INT4/FP8 不进入首期验收。
- 保留 Granite 特有缩放：embedding×12、residual×0.22、attention×1/64、logits÷6；RMSNorm eps=1e−6、RoPE theta=1,500,000。尤其 attention 不是通常的 1/√64。
- 路由为 **先取 top-8，再对选中 logits 做 softmax**，不以所有 32 个专家 softmax 的未重归一化值替代。相同 logits 的 tie 规则必须与 golden 对齐；脑测采用小 expert ID 优先，未假定 HF 的 topk tie 保证。[官方参考实现 v4.46.0](https://raw.githubusercontent.com/huggingface/transformers/v4.46.0/src/transformers/models/granitemoe/modeling_granitemoe.py)

真实权重尚未下载和量化，故不声称量化精度、困惑度或语言生成质量通过。

### 4.3 算子范围与主机边界

| 路径 | LPU 目标映射 | 首版边界 / 未闭合项 |
|---|---|---|
| QKV/O、QKᵀ/AV、专家三矩阵、router linear、LM head | MXM 分块 GEMM / GEMV，FP32 partial sum | native MXM、布局/装载、结果累加及长组合路径待解决 |
| RMSNorm | VXM 平方、归约、Rsqrt、缩放 | 归约与特殊函数精度/时序尚未完整验证 |
| causal softmax | max/sub、Exp、sum、Recip、乘 | mask、稳定性、归约和 special LUT/算术验证未完成 |
| SwiGLU / 残差 / 专家混合 | Exp/Recip 实现 SiLU，mul/add/scale | 不需要 Log；不能把 main 的 Log 自动并入 develop |
| RoPE | 主机预生成 sin/cos，LPU 做旋转乘加 | 无需新增硬件三角函数；表搬运与位置索引需验证 |
| TopK、专家分桶与发射 | **首版主机执行**，每阶段完成后再发后续静态计算 | 动态运行时边界需明确；不得宣称全硬件自主 MoE |
| tokenizer、embedding gather、greedy argmax | **主机执行** | 纳入端到端时延统计，不隐藏 CPU 时间 |

片内执行采用“**搬运完成 → 冻结本阶段输入 → 执行静态 schedule → 回收完成/路由 → 下一阶段**”。不能直接把 DDR 的变长 ready/valid 等待塞进普通 readyless SRF。

### 5.2 真实 24 层形状的外推

以下按上述真实配置公式计算，无权重实跑；不含对齐填充、descriptor、代码与 DDR 控制器保留空间。MiB/GiB 使用二进制单位。

| 项目 | 结果 | 含义 |
|---|---:|---|
| 全 BF16 权重 | 约 **2.486 GiB** | 板载 8 GB 足够容量，不能放入 3.25 MiB MEM |
| 混合 W8/BF16 总权重 | **1,425,901,568 B ≈1.328 GiB** | 包括 38.25 MiB BF16 scales，以及 BF16 router/norm/共享 embedding |
| 单个专家三矩阵 W8 | **1.5 MiB＋48 KiB scale** | 两个整专家双缓冲已基本吃满 MEM，须继续分块 |
| 单层 W8 主矩阵 | **51 MiB**，尚未加 scale/router | 仅一个完整 block 也依赖片外存储 |
| 每 token 每层激活的 8 个专家 | **12 MiB W8**，不含 scale | top-8 降算量，不消除全部 32 专家常驻片外存储 |
| 全 24 层 KV，S=32/B1/BF16 | **1.5 MiB** | 公式：2×24×32×8×64×2 B |
| KV，S=64 /128 | **3 MiB /6 MiB** | 64 几乎挤掉工作区，128 已超当前 MEM 总容量 |
| decode 线性 MAC/token | **428,605,440** | 含 router 和 BF16 LM head；context24 的 attention 再加 1,179,648 MAC |
| prefill16 线性 MAC | **6,102,712,320** | LM head 仅计算最后一个位置，不算所有 token 的无用 logits |

**带宽压力比权重容量更值得关注。** 若每次 decode 都从 DDR 读取当步所需的矩阵/scale/router/LM head，且无持久权重缓存，约 **468.75 MiB/token**。假设有效 DDR 带宽为 1 /8 /16 GB/s，仅这部分传输下界为 **491.5 /61.4 /30.7 ms/token**；未计计算、KV、主机调度等，不能倒数后宣称实测 tokens/s。

1GbE 原始上限只有 0.125 GB/s，逐 token 搬这些权重至少约 3.93 s。故 HTG-960 的以太网应**一次预装到板载 DDR**，运行时从板载 DDR 取权重，不经主机逐 token 重传。

### 5.3 片内分块与 MoE 最坏情况

建议的容量草案：104 slices 按 4 slices/group 为 26 个 128 KiB group，总 3.25 MiB。

| 逻辑用途 | groups | 容量 |
|---|---:|---:|
| 24 层、32 context KV | 12 | 1.5 MiB |
| 权重双缓冲 staging | 4 | 512 KiB |
| 激活/partial sums/路由工作区 | 6 | 768 KiB |
| 保留 | 4 | 512 KiB |

每半球按 6/2/3/2 groups 容量对分，只是先验字节预算。尚未证明物理位置、MEM role、读写端口、stream 地址或跨半球时隙可实现，后续必须用编译器/周期模型检查。

128×128 W8 权重 tile 为 16 KiB＋512 B scale，反量化成 BF16 为 32 KiB，可在上述 staging 内分块双缓冲。不能把这一容量 tile 的16×16计算切分当成已经确定的 native MXM 几何。

Prefill16×top8 共 **128 条 token-expert 派发**；平均每专家 4 条不能当容量保证。极端时同一批 16 token 可全部选中同样 8 个专家，每个热门专家 16 条。复制全部 routed input 需 256 KiB；首版 **dropless、逐专家/分块处理**，不按均值分配后静默丢 token。

## 6. 当前最大问题及回退顺序

| 优先级 | 实际障碍 | 本轮判断 / 回退 |
|---|---|---|
| P0 | native 全系统 LPU16 尚未统一 | 先冻结 native top、MXM 几何/延迟与 MEM/SRF ABI；继续模块测试，不能报完整上板资源 |
| P0 | MXM 无流水长组合路径 | 先等功能规格化和尾数结构优化，再设计流水/分拍合同；流水需要连同 schedule、valid、累加依赖一起审核 |
| P0 | 外存和动态 MoE 的完成语义 | 首版主机协同、明确完成边界的分阶段预取；补 DMA Load、外存 completion、fence，不能把 Store sink accept 当写回完成 |
| P1 | 3.25 MiB 放不下权重/较长 KV | 权重常驻 DDR 并按 tile 流式读取；context32，B1；必要时只演示一层或缩短输入，不改硬件容量 |
| P1 | special 算子和浮点差异 | BF16 基线优先；必要时把 norm/softmax/SwiGLU 暂留 CPU，明确标记“MXM/混合加速演示” |
| P1 | 整机面积与跨 SLR 可布线性未知 | 主推 VU19P；若仍不满足，先做功能相同的后端结构优化；时间复用或多 FPGA 需要新增架构审批，不用隐式剪裁冒充同配置 |

远程 [C2C/DMA 状态文档](https://github.com/WongWangKit/FTLPU-VMODEL/blob/a8fb96a377a3d7b8269b8ea86d28019559cd2127/docs/c2c_dma_status.md) 将当前 DMA Store 定位为 vector-sink / single-lane baseline，DMA Load、外存请求/完成、dispatcher、descriptor/ICU 队列与 Sync/fence 尚未闭合；C2C 仍是 credit/serialization 抽象，PHY/CDC/framing 等未实现。买 HBM 板或更大 FPGA 都不会自动补齐这些合同。

**推荐回退顺序：**24 层 → 1 个原宽度完整 block → Direct16 BF16 → host-assisted 特殊算子/路由 → 单模块诊断 bitstream。最后一项不是完整 LPU16 验收。需修改物理并行度、精度支持、Block8 或周期合同的方案另行确认。

时钟也不能靠一句“先降到 50 MHz”解决：优化单列预布局路径仍约 **77.8 ns**，20 ns 预算远不足。可试低速诊断，但仍需完整 post-route STA；不得用没有真实握手/稳定周期依据的 false path/multicycle 掩盖路径。

## 7. Vivado 综合优化到底证明了什么

### 7.1 各模块的实际结果

历史统一对照使用 Vivado/XSim 2023.2、VU9P、OOC；多数在综合前施加 10 ns 时钟/虚拟时钟及 1 ns IO，MXM 单列采用相同 `-no_timing_driven` 面积策略后做 STA。**不是三块目标板各自的综合结果。**

| 模块 / 实测粒度 | 优化方式与结果 | 已解决 / 仍未解决 |
|---|---|---|
| MEM 1024×64 leaf | 从 RAM 数据通路的异步复位过程解耦，控制单独复位；同步读写，冷启动 INIT 为零、执行复位保留数据；再指定 `ram_style=block/ultra`。得到 **74 LUT＋12 FF＋2 BRAM36** 或 **1 URAM** | 原始过程未推断 RAM 时曾达 18,631 LUT＋65,611 FF。属性须建立在合法 RAM 模板上；不消除 slice 外围选择网络 |
| MEM slice | 旧局部测量 **4,953 LUT＋284 FF＋8 BRAM36** | 104 slices 外推仍约 51.5 万 LUT；RAM 映射完成不等于总 MEM 逻辑很小 |
| SRF leaf | 唯一合法源 one-hot 重写：**2,934→2,888 LUT**，仍 **2,304 FF** | 仅省1.6%；256 cells 同时独立更新/可见，256×(8 data+1 valid)正好2,304 FF。不是深度 SRAM，不能加 RAM_STYLE 就改成少量 BRAM |
| VXM basic ALU | 默认 2,538 LUT/0 DSP；九个小乘法强制 DSP 为 1,868 LUT/**9 DSP**；推荐有效格式掩码＋24×24 宽尾数 DSP 为 **1,513 LUT/2 DSP**，FF109 | LUT −40.4%，保留 FP16/BF16/FP32。100MHz WNS **−2.493 ns**，仍未达标 |
| MXM 标量 FP16/BF16 乘法 | 默认与单加 `use_dsp=yes` 均 **310 LUT/2 DSP**；利用低13bit恒零，11×11 有效尾数精确对齐后 **195 LUT/1 DSP** | 默认已推断 DSP，单加属性无增益；代数化简而非削减有效精度 |
| MXM 8 项点积单列 | 默认 **16,182 LUT/16 DSP**；窄尾数 **14,999/8**；再改规格化为前导零计数＋一次 barrel shift，**8,313/8** | LUT −48.6%；WNS **−308.303→−69.796 ns**，依然不具备 100MHz 运行条件 |
| SXM / result buffer | transpose 主体是字节排列连线；浅层、多位同时可见 result buffer 更接近 FF | 无本轮面积数据，不能按大 SRAM 指望靠属性大幅省 LUT |
| VXM special / paired LUT | 需分别检查 Exp/Recip/Rsqrt、浅 LUT RAM 和管线；浅小表可用 distributed RAM，BRAM 也可能浪费容量 | 尚未完成统一综合与误差/时序验证，不给虚构资源数 |
| ICU / DMA / DDR / host shell | 后续对控制、FIFO、深 buffer 分层综合；可推断深 RAM，必须符合端口和复位语义 | 功能集成本身未闭合，不能当作“零资源”并从预算中遗漏 |

MEM leaf 两版 WNS +7.701/+7.256 ns，SRF 两版 +6.819 ns，仅代表所测局部约束。VU19P 只有 320 URAM，416 个 leaf 若每 leaf 占一个 URAM 就放不下；因此主推 **832 BRAM36**，必要时按物理位置混用 URAM，不强行统一 ultra。

### 7.2 点积阵列在哪、为什么路径长

调用关系：`lpu_mxm_slice → lpu_mxm_compute → lpu_mxm_dot_bank`。它负责 GEMM 的局部乘加：每个输出列计算 `sum(a[k]×w[k,j]), k=0..7`；旧 bank 同时产生 32 列，compute 再做跨 tile 累加。

- 8 个乘法可以并行，**输出列之间也并行**；不是 32 列串成一条路径。
- RTL 的 for 循环没有时钟边界时会展开为组合硬件。旧代码按顺序调用 FP32 add，形成约 7 次真正的浮点加法依赖（第一项加零可化简）。
- 每一级又有指数对齐、加减、规格化、舍入。旧规格化最多 26 次条件移位/指数递减形成深级联。
- 优化保留原累加顺序和舍入点，只改变等功能结构：原单列 **1,166 个逻辑层级、316.278 ns 估计数据路径**；compact 为 **305 层、77.771 ns**。后者含 21.738 ns 逻辑、56.033 ns 预布局估计布线。
- DSP 属性只能改善乘法等映射，**不会自动新增对外可见的流水周期**。换成加法树会改变浮点结合顺序；增加寄存器/复用算术会改变延迟和吞吐，需要新的架构合同与回归。

这些是综合后估算路径，不是布线后实测频率；旧 ASIC/DC 时序也不能代替 FPGA 时序。

## 8. 下一阶段的明确验收门槛

1. **版本/接口**：native top 统一到确认的 LPU16；给出 MXM 数量/几何、模式、流水和累加合同。解决旧顶层的 Vivado 前端兼容点；旧 `lpu_vxm_tile_execution.sv` 中保留字 `config` 仍需处理，不能把旧顶层当成一键可综合。
2. **后端**：审核接入可选 MEM BRAM/URAM、VXM 宽 DSP、MXM 有效尾数/compact normalization；保持原容量和合法指令语义。任何新流水/时分复用都更新编译调度合同。
3. **完整资源**：先分层再全核综合；加入真实 DDR、主机接口与 ILA shell。主推 VU19P 初期以总 LUT≤2.86M、DSP≤2,688、BRAM36≤1,512 为预算，超预算必须重新分析而非直接判定失败。
4. **时序/板级**：原型可先以 50MHz 为设计目标，但要通过全时钟、IO、CDC 和 post-route STA；当前 MXM 没达到。完成 DDR校准/压力测试和主机搬运/完成闭环后，才进入 R1。
5. **数值**：用固定真实权重导出同布局 BF16 与 W8 golden；传输/地址/路由零错；算术依据约定舍入合同检查。先定量评估逐层误差、路由差异、teacher-forced logits，再决定量化质量阈值，不能用随机模型的10项PASS代替真实精度验收。
6. **演示**：R1完整block通过后跑R2；报告 CPU、DMA、LPU 各阶段时间、实际 DDR 字节量、时钟、温度和 tokens/s，不仅给算术峰值。
