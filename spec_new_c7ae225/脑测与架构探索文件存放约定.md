## 1. 文件放在哪里

| 文件类别 | 保存位置 | 内容 |
|---|---|---|
| 当前设计方案、参数化方案、接口契约、待确认问题 | `lpu_src/FTLPU-VMODEL/spec_new_<基线>/` | 当前讨论和实施所依据的文档；已确认要求、推荐选项、待确认问题分别标明 |
| 架构探索、代码调研、手工脑测、方案比较 | `lpu_src/FTLPU-VMODEL/spec_new_<基线>/exploration/<模块>/` | 假设、逐拍推演、代码依据、资源估算、实验结论和建议 |
| 可运行脑测模型、探针、用例及绘图脚本 | `learn/<模块>_<课题>_<YYYYMMDD>/` | 按一次研究课题建立实验目录，保留可复现入口 |
| 脑测与实验的留存结果 | 上述实验目录的 `results/<运行编号>/` | 检查结果、关键 CSV/JSON、运行日志、必要波形和结果摘要 |
| 实验临时产物 | 上述实验目录的 `tmp/` | 编译产物、可重建源码快照、渲染帧、预览图、临时转换文件 |
| 交付用架构图、GIF、关键步骤位图、SVG | `doc/arch_pics/<模块>/` | 对话、设计文档和 PPT 引用的成品图片 |
| PPT 及其制作说明 | `doc/PPT/` | 演示文件及对应内容规划 |
| 设计文档修改前备份 | `lpu_src/FTLPU-VMODEL/spec_new_<基线>/archive/<日期_事项>/` | 需要保留的旧版文档与整理记录 |

当前 SXM 文档采用 `spec_new_c7ae225`。每份探索报告另行记录实际检查的 VMODEL/CMODEL 提交；目录名表示所属设计资料集，实验基线以报告记录为准。

## 2. 新实验目录建议结构

```text
learn/<模块>_<课题>_<YYYYMMDD>/
  README.md                    # 要回答的问题、运行入口、基线及结果索引
  scripts/                     # 模型、探针、检查器、绘图脚本
  cases/                       # 输入数据、配置和预期结果
  results/<YYYYMMDD_HHMM_用例>/  # 一次运行的留存依据
    summary.md                 # 条件、结论、验证范围与遗留问题
    ...csv / ...json / ...log
  tmp/                         # 可重建的中间产物
```

目录按实际需要建立。简单实验可以在根目录保留一个运行脚本与 README，结果仍按运行编号保存。

被设计结论引用的数据、日志和检查结果保存在 `results/`。重跑时新增运行编号，便于比较前后结果。大型全量波形只保留必要部分；摘要记录筛选范围与完整数据的重建方法。

## 3. 每次脑测、实验记录什么

- **手工脑测**：问题、输入数据、假设、逐拍数据去向、存储占用和推导结论，写入探索报告。
- **可运行实验**：保存运行命令、脚本版本或哈希、VMODEL/CMODEL 提交、LPU 配置、数据类型、输入用例、检查规则和结果文件。
- **验证层次**：分别写明手工推演、独立模型检查、CModel 运行、RTL 仿真、综合的实际完成情况。
- **结论状态**：区分已确认要求、实验观察、推荐方案和待确认选择。实验通过后，技术选择继续按原审核流程处理。
- **图与实验对应**：报告或实验 README 记录成品图路径、生成脚本、输入结果和适用方案。图的说明留在这些文档中，`arch_pics` 保存图片。

## 4. 命名与引用

- 探索报告用 `<课题>_<YYYYMMDD>.md`；当前主方案保持原文件名。
- 脚本和结果用简短、可辨认的课题名；必要时加入 LPU 配置、模式和运行编号。
- 成品图沿用已有明确名称。关键帧可追加 `tNN` 或 `CNNN`，相关报告解释周期起点。
- 报告引用实验目录与结果；实验 README 反向链接报告和成品图。正式采用后，从主设计文档链接对应依据。
- 文件移动时检查引用，保留文件内容和原有审批状态。
- 准备清理 `tmp/` 时，先核对报告引用并留存证据。仍被历史报告直接引用的文件按待整理资料保留。
