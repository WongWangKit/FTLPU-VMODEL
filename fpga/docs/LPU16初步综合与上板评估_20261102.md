# LPU16 初步综合与上板评估

## 结论

**完整 LPU16 不能按“旧顶层缩 SRAM 后直接放进 VCU118”推进。** 旧顶层是固定 32-lane、4-MXM 结构，尚未集成 native MEM/SRF；当前前端还被 SystemVerilog 保留字 `config` 阻塞。新 LPU16 的资源压力主要在 MEM 流选择网络、SRF 和逐 lane VXM，而非单纯 SRAM 字节数。

推荐两条明确区分的路线：

用户后续已确认采购预算无上限：以下路线 1 为主线；路线 2 仅作为已有板快速验证的备选，不因板价主动削减正式 LPU16 功能。

1. **保留完整 LPU16 结构**：以 **HTG-960/VU19P** 作为资源主候选，继续补齐 native MXM、special ALU 和系统 shell 的资源预算后再采购。4.09M LUT 提供明显更大的逻辑余量；3840 DSP 仍需专项核算。
2. **若已有 VCU118，优先复用做演示**：先完成模块级测试；另立 16-lane、每侧 16 MEM slices、BF16 basic 计算的 compact demo 方案。其可测部分外推约 474k LUT，尚不含 MXM 等模块；不是正式 LPU16 的整机综合结论。当前尚未确认团队板卡库存。

本轮已取得 **5 个完整局部综合结果**（MEM leaf、MEM slice、SRF leaf、三格式 basic ALU、固定 BF16 basic ALU），并为其中可独立检查的模块运行 RTL 与 post-synthesis functional simulation。没有生成整机 bitstream，没有执行布局布线或真实板测。

## 实际综合结果

以下均为 OOC 综合，顶层输入保持动态、输出保持可观察；没有把数据入口接零来制造面积缩小。共同报告约束为 10 ns 时钟、1 ns 输入/输出预算、异步复位输入 false path。约束在综合后加入用于初步报告，**不是已按 100 MHz 优化并通过实现的设计**。没有布线寄生、完整 clock skew 或板级约束。

| 实测对象 | 配置和范围 | LUT | FF | BRAM36 | DSP | 10 ns 报告 WNS |
|---|---|---:|---:|---:|---:|---:|
| FPGA MEM leaf 实验后端 | 1024×64-bit，单口，固定一拍读 | 74 | 12 | 2 | 0 | +7.701 ns |
| native MEM slice + 实验后端 | 2 banks × 2 tiles，全部 stream 选择和 fault 逻辑 | 4953 | 284 | 8 | 0 | +6.932 ns |
| native SRF lane leaf | 32 streams × 8 lanes，2 producers/2 consumers，单列单方向单 tile | 2947 | 2304 | 0 | 0 | +6.819 ns |
| VXM basic 实验 wrapper | FP16/BF16/FP32，移除永不启用的 special 分支 | 2393 | 109 | 0 | 0 | **−3.474 ns** |
| VXM basic 固定 BF16 wrapper | unpack 和 arithmetic 都固定 BF16 | 588 | 60 | 0 | 0 | +1.663 ns |

证据：[MEM 与 SRF 综合结果](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/run007)、[三格式 basic 结果](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/run010/alu_basic_pruned)、[正确固定 BF16 结果](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/run012/alu_basic_bf16)。成功案例的 `checks.txt` 检查黑盒和 latch，`drc.rpt` 留存该阶段 DRC。

原版 `lpu_vxm_alu SPECIAL_KIND=0` 已生成相同的 **2393 LUT/109 FF** utilization 报告，但整体脚本在后续 timing 阶段达到 600 秒上限，未导出完整网表；只承认其已生成的面积报告。[run009 原版 basic](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/run009/alu_basic)

`DSP=0` 表示本次工具将这些小乘法映射到 LUT，并非模块没有乘法。special ALU、完整 MXM 和完整 VXM Tile 没有可采纳的完整资源数字，不能以零填补。

## SRAM 映射问题与实验修复

当前 native `mem_bank_superlane_leaf` 把 RAM 写操作和异步复位控制放在同一个敏感块。Vivado 报告：

> RAM is sensitive to asynchronous reset signal. this RTL style is not supported.

随后将 1024×64 存储展开为 **65,536 个数据 FF**。综合内部统计另有 75 个控制/输出 FF；416 个 leaf 单是数据就需要 27,262,976 FF，无法作为本项目 FPGA 存储实现。[原始诊断日志](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/run004/mem_leaf/console.log)

`test/20261102_initial_synth/rtl/mem_leaf_bram.sv` 保留相同命令/数据端口，把 RAM 移入无异步复位的时钟块，保留控制的异步复位；用 `have_read_q` 保持 reset 后读输出为零、SRAM 内容保留以及首次读后的数据保持语义。BRAM 配置 INIT 实现冷存储 epoch 读零，不在执行 reset 时清阵列。本轮只证明该 FPGA 实验后端，未推广到 ASIC SRAM 宏。

原始 MEM leaf 的后续单线程综合已产生 DCP，但大网表导出达到 240 秒上限；该运行不能整体标为 PASS。由 DCP 成功补导的资源报告确认为 **18,631 LUT、65,611 FF、0 BRAM**，与实验后端的 74 LUT、12 FF、2 BRAM36 对比；原版时序未取得有效报告。[恢复资源报告](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/recover001/utilization.rpt)

旧 `lpu_mem_tile_slice_behavior` 还有异步 host SRAM 读和异步指令读，不能直接套用同步 BRAM 而不改变旧时序。该对象的 1024 行直接综合在 600 秒限额内未完成。旧 SRAM 宏分支是 ASIC 风格的 2048 行、逐 bit 写掩码接口，也不自动等价 FPGA 最佳映射。

## LPU16 资源外推

以下是**独立 OOC 实例数乘法**，用于筛选候选和发现瓶颈；不是整机资源上界、下界或综合结果。系统集成会改变共享、常量传播、跨层优化和布线，不应把百分比视为装载保证。

| 部分 | 实例数依据 | 外推 LUT | 备注 |
|---|---|---:|---|
| MEM slices | 2×52=104 | 515,112 | 832 BRAM36；不含 group/hemisphere glue |
| SRF leaves | 2 半球×2 方向×16 列×2 tiles=128 | 377,216 | 294,912 FF；独立输入的通用 2-producer leaf |
| VXM basic 部分 | 16 lanes×16 ALU 位置=256 | 612,608 | 还未加 special 增量、operand MUX、转换器、链路控制及 LUT 存储 |
| **上述合计** | 全格式 basic | **1,504,936** | VCU118 总 LUT 的约 **127.3%** |
| **上述合计** | 仅将 basic compute 固定 BF16 | **1,042,856** | VCU118 约 **88.2%**，仍未计 MXM 等 |
| compact 对照 | 每侧 16 MEM slices、SRF 7 列、BF16 basic | **474,056** | VCU118 约 **40.1%**，改变拓扑且未实现 |

公式及可重算数据：[projection.json](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/analysis001/projection.json)、[measured_resources.csv](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/analysis001/measured_resources.csv)。

全配置 MEM payload：`2×52×2×2×1024×8 = 3,407,872 B = 3.25 MiB`；832 BRAM36 为 VU9P/VU19P 的 38.5%，却是 ZU9EG 的 91.2%。因此 ZCU102 即使只看 MEM 也没有合理系统余量。

这组外推说明：**优先解决 FPGA 后端和逻辑映射，完整结构选更大 LUT 器件；缩小 SRAM 深度本身不足以解决问题。** VU19P 可给该 1.505M LUT 小计留下约 2.58M LUT，但 native MXM/special/DMA 的实际资源与跨 SLR 时序仍必须补测。

## Post synthesis 功能仿真

采用 XSim、Xilinx `unisims_ver` 和 `glbl`，等待 GSR 初始阶段结束后驱动相同 TB。使用 `write_verilog -mode funcsim` 生成网表，**没有 SDF 标注**；测试覆盖功能，不验证实际 100 MHz 时序。

| 对象 | 自检内容 | 已取得结果 |
|---|---|---|
| 原版 native MEM leaf RTL | 1024 行冷零、全地址伪随机写/读、WriteTap、非法地址/opcode、reset 后数据保留 | RTL 4619 checks PASS |
| 实验 BRAM 后端 | 同一 MEM TB，同一 scoreboard，无 DUT 数学/存储函数复用 | RTL 与综合网表各 4619 checks PASS |
| 原版 SRF leaf | 遍历 256 个 stream/lane 单元、128 组随机多源/consume、冲突、清空及复位 | RTL 与综合网表各 385 checks PASS |
| 原版 basic ALU RTL | 三格式 Add/Sub/Mul/Negate/Max/Bypass、NaN/Inf/subnormal、保留格式/opcode | 21 个算术向量及拒绝检查 PASS |
| 三格式 basic wrapper | 同一组端口级精确 bit-pattern 期望值，乘法两拍、其他一拍 | RTL 与综合网表各 21 个向量及拒绝检查 PASS |
| 固定 BF16 basic wrapper | BF16 基本与异常数向量；遍历未使用格式引脚的 4 种值 | RTL 与综合网表各 36 个向量及拒绝检查 PASS |

日志索引：`sim001` 原版/实验后端/SRF RTL；`sim002` MEM gate；`sim003` 原版 ALU RTL；`sim004` SRF gate；`sim005` basic wrapper RTL/gate；`sim006` 固定 BF16 RTL/gate。每项记录命令、退出码、TB 副本和 SHA256。MEM slice 本轮完成综合但未运行 slice 级综合网表仿真。

## 未通过项目和原因

- **旧顶层**：`lpu_vxm_tile_execution.sv` 第 100 行声明函数参数 `config`，第 257 行等继续使用该 SystemVerilog 保留字，Vivado 报 Synth 8-2716/8-10307；随后 top 不可展开。没有旧整机综合网表和整机 post-synthesis PASS。[明确的旧顶层运行日志](C:/Users/huazh/Desktop/LPU/lpu_src/FTLPU-VMODEL/fpga/test/20261102_initial_synth/results/run011/old_top/console.log)
- **算术单元测量范围**：首次使用全旧 filelist 也因无关 tile 文件的语法而失败；后续叶模块使用最小依赖集合。special 分支运行还遇到 Vivado 安装 Tcl 文件间歇读取错误；旧 dot 在 run007 的 600 秒有界综合中超时，run011 重试遇到工具文件读取错误，没有可采纳的 DSP/LUT 结果。
- **运行环境**：沙箱内 Tcl `file normalize` 返回错误路径及 `.Xil` 清理失败；后改为明确绝对路径并在授权环境运行。部分 Vivado 辅助进程仍报告现存安装 Tcl 文件不可读，根因尚未定位。已完整完成的报告/网表/自检可单独采纳；环境失败不算设计失败。
- **实验纠错**：`run010/alu_basic_bf16` 仅固定 unpack 而漏接 arithmetic 格式，已标 `INVALID_FOR_PROJECTION.txt`，不得使用其 1789 LUT 或时序。`run012` 修正并增加 4 种格式引脚扫描。原版/三格式 wrapper 不受该固定格式错误影响。
- **实现层级**：未进行系统 CModel 对比、native 整机仿真、P&R、CDC、功耗评估、MIG/PCIe 驱动验证或上板。保留既有 MXM 跨模块延期问题，没有修改其调度来制造测试通过。

## 下一步建议

先审核并接纳 FPGA RAM 后端，再固定 native LPU16 的 MXM/VXM/SXM 接口与文件清单；对 MXM、special ALU、一个 MEM group 和一段真实连接的 SRF 做独立综合，减少纯 leaf 外推误差。随后选择完整结构的大 LUT 板或明确的 compact demo，在 50 MHz 下集成最小 host shell 并完成布局布线。采购决策应在该集成资源结果之后。
