# MXM 时序与输入调度约定

修订：0.4。日期：2026-11-09。适用对象：当前新版 `lpu_mxm_core`，
不适用于旧 `lpu_top` 的 legacy MXM。

本文件定义编译器、输入数据供应方、RTL 和验证环境共同遵守的外部行为。
文中的“必须”表示合法输入/调度的条件，“硬件保证”表示满足这些条件后的
固定行为。它不是新增硬件配置项，也不会让硬件自动补齐、插空拍或重试。

调度模型和相关验证。修改文档本身不构成 RTL 已满足约定的证明。

## 2. 时间和数据粒度

所有周期编号均为同一时钟的上升沿，`E0` 必须注明对应的事件：

| 术语 | 精确定义 |
|---|---|
| 入队 | enqueue valid/ready 握手，指令进入 FIFO；不启动执行 |
| 发射/本地指令更新 | launch 被接受，该列/该 superlane 的当前指令寄存器更新 |
| 数据可用 | 指定时钟沿之后，发送方的输出数据和 valid 已稳定 |
| 采样/消费 | 接收方在指定时钟沿采样此前已经稳定的数据和 valid |
| SRAM 请求服务 | Bank 在该时钟沿实际接受一次读或写 |
| 写入提交 | 该时钟沿之后，对应 SRAM 地址的新值已提交 |

例如顶部结果在E21沿后可用，经过四级回传后在E25沿后到达左端，后端
在E26采样；不能把可用沿和采样沿称为同一时刻。
II=1表示稳态每拍可处理一批，不表示一批只经过一级，也不保证任意非法
输入或地址序列都能无冲突运行。

当前默认配置：

| 属性 | 数值/含义 |
|---|---|
| Supercell 阵列 | 4行 × 4列，每个为8×8权重 |
| 逻辑一批 activation | MATRIX_K=32个BF16，分成4个K段，每段8个 |
| 一列 Supercell 的结果批次 | CELL_N=8个同时有效的FP32 |
| 整个阵列的一批结果 | MATRIX_N=32个FP32，4列之间各晚一拍 |
| 结果回传 | 列c向下到行c，再向左；默认各路径固定4拍 |
| 累加器物理位置 | 各Superlane左端，行c接收原顶部列c的8个FP32 |
| 计算 COUNT | activation逻辑批次数32～1024，指令使用10位COUNT−1编码 |
| 前端指令宽度 | 计算17位；权重加载8位，无列地址 |
| 后端 COUNT | 一列结果的连续批次数1～1024，10位COUNT−1编码 |
| 后端指令宽度 | 默认23位：格式1位、COUNT−1为10位、逻辑地址10位、操作码2位；地址随深度变化 |
| SRAM 逻辑批次地址 | 每个地址保存本列8个FP32，默认深度1024 |

COUNT不表示K维元素数，也不表示输出lane数。四行处理同一个逻辑
activation 的不同K段，必须按行间相位提供，不能把四段都在同一拍消费。

## 3. 指令和输入供应责任

计算、权重加载、后端累加/存储各有独立 FIFO 和 launch。
计算/加载/后端分别使用17/8/默认23位紧凑格式，不允许将以前的共用64位
前端字直接接入窄端口而依赖截断。计算无操作码与版本位，加载只保留
MATRIX/COLUMN模式位。外部入队端口决定目标队列。

编译器/指令供应方必须：

- 让目标指令在launch之前已处于队首，并满足launch_ready。空队列同沿
  入队不能使这条新指令立即发射；正常满队列可按ready完成同沿出队/入队。
- 分别安排三条指令流，不把权重加载或后端操作隐含在计算指令里。
- 先验证计算COUNT为32～1024，再编码COUNT−1。长任务分段时每段仍需
  满足32批下限，禁止1024+不足32的尾段；填充及Bank相位约束另行满足。
- 对当前计算有效的每个row输入槽提供activation_valid和完整的CELL_K个
  BF16；对加载有效槽提供weight_valid及完整权重拍。缺拍不会延长COUNT。
- 在采样沿前准备好数据、valid和必要控制；不能依赖接收方等待。
- 保证源数据与本行的指令、row_index、buffer选择一致。

前端只在对应执行窗口消费输入，窗口外的数据不被当作额外计算或加载。
后端则要求新部分和与其执行槽严格一一对应，多批、缺批或错相位会报错。
一个时钟沿同一列只有一批新部分和，不能同时用两条后端操作重复消费它。

硬件保证固定流水和固定COUNT推进。数据通路没有ready/backpressure、
自动停顿、自动重试或累加结果到操作数的反馈旁路。

输入算术类型当前为BF16，采用输入DAZ；中间点积、部分和及SRAM保存FP32。
输出可选择FP32或BF16，数值规则见算术文档。数据维度不足配置宽度时，
供应方必须构造完整物理输入；未使用K项的activation和weight均补零，
不能靠省略valid或缺少lane来缩短一次物理运算。

## 4. 前端传播与阵列结果

设底层计算指令在S更新，行号r从底向上、列号c从左向右，均从0开始。
当前dot流水为9级，上行FP32加法为3级，水平activation链接每级一拍：

| 事件（第一批） | 时刻 |
|---|---|
| 行r本地指令更新 | S+3r |
| 单元(r,c)的M1采样 | S+3r+1+c |
| 该单元本地点积可用 | S+3r+9+c |
| 该单元向上合并结果可用 | S+3r+12+c |
| 顶部列c阵列结果可用，默认4行 | S+21+c |
| 左端Superlane c回传结果可用，默认4行 | S+25+c |

### 4.1 固定向下/向左回传

完整核心在顶部计算结果与累加器之间实例化 `lpu_mxm_result_return`。
本实现支持参数化方阵，要求ROWS==COLS；非方阵在启动仿真/检查时明确
拒绝，不进行隐含复制、丢列或动态仲裁。行号从底向上，转向位置为(r,c)=(c,c)。

每个r>c位置有一组向下寄存器，每个r>=c位置有一组向左寄存器；
交叉位置两组独立，可同时携带不同来源/标签的批次。其余方向或位置
不生成数据寄存器。默认向下6组、向左10组，每组8×32 bit，另外同步
保存valid和16位标签。方向与连接由generate静态决定，无动态路由开关。

顶部列c路径包含ROWS-1-c级向下寄存器和c+1级向左寄存器，总计ROWS级。
其中向左级数包含对角转向寄存器，以及同一路径上的左端输出位置；
左端寄存器之后直接接累加器，不另加未计入的寄存级。
4×4时顶部列0在E21可用则左端行0在E25可用；顶部列3在E24可用则
左端行3在E28可用。各路径等长，保留相邻Superlane一拍错位，不补成同拍。

`partial_*_o`保留原顶部监测语义；`returned_*_o`是实际左端累加器入口。
回传不执行算术、不改变FP32编码，valid空拍按同样路径传播。
run停止或复位清除两路在途valid，不会重放之前取消的结果。
RTL规定邻接连接；寄存器的物理邻近仍需要后续布局约束和时序验证。

底层上行加法仍以加零经过三拍。各层上行加法要求本地点积、下方部分和
在入口同拍有效且事务标签一致。标签用于流水对齐，不代替编译器逻辑地址。
当前16位标签自然回绕，外部不能假定它是无限增长的全局张量ID。

同一计算指令COUNT为B时，每行连续消费B批。下一条在S+B更新，可以
无空拍接续；旧指令已进入流水的数据继续完成。多行前端队列的最小
发射间隔为max(该指令本地持续拍数,3)，并非等待最顶层接收完成。
MATRIX持续MATRIX_N拍，COLUMN持续1拍；因此默认COLUMN同队列至少
间隔3拍，COMPUTE和MATRIX默认至少间隔其各自COUNT或32拍。

## 5. 权重乒乓加载

MATRIX每行入口按全局输出列MATRIX_N-1到0输入，共MATRIX_N拍。
数据、valid、buffer ID在每个Supercell边界一起寄存。COLUMN执行一次同样
的权重移位，MATRIX连续执行MATRIX_N次；两种模式共用原有尾部链路，
没有定点写入、地址包或第二条COLUMN数据通路。命令结束不清在途尾部。
从空Buffer填充时，供应方必须送足完整列序列；只有一次COLUMN不会使
整个阵列获得一套完整权重。交替Buffer的输入各自保持独立的加载顺序。

设MATRIX在底层W发射，则行r入口在W+3r+1采样第一拍，列c最后一拍
写入在W+3r+MATRIX_N+c。随后计算必须满足本地最后写入先于M1采样；
统一使用S>=W+MATRIX_N即可满足同一块权重在各行各列的完成相位。

同一个单元在M1采样沿不能重写正在使用的weight buffer，即使更新的是
该buffer内另一个输出组。M1之后的算术级不再占用权重寄存器。
`weight_buffer_ready`只表示各组写过，不表示“本次新矩阵全部完成”，
不能据此省略完整加载或版本相关调度。

默认连续32批的合法实际输入窗口：

| 左端周期 | activation | 同时输入的权重 |
|---|---|---|
| E1～E32 | 尚未启动 | 第一套B0 |
| E33～E64 | 使用第一套B0 | 第一套B1 |
| E65～E96 | 使用第一套B1 | 下一套B0 |
| E97～E128 | 使用下一套B0 | 下一套B1 |

SC c最后使用旧B0在E64+c，重载从E65+c开始，完成于E96+c，E97+c
使用新B0。两条波形具有相同水平相位，不需要整行3拍保护间隔。
对于其他阵列规模，要隐藏权重加载需要当前计算批次覆盖MATRIX_N拍；
默认MATRIX_N=32，因此每批计算COUNT>=32即可容纳下一套权重加载。
这描述的是权重带宽条件，不能替代后端Bank/地址合法性检查。

## 6. 后端从会合时刻倒推

后端四种操作为DIRECT_OUT、STORE、ACC_STORE、ACC_OUT。
设左端Superlane 0第一批回传部分和在P沿后可用，则后端必须在P-2更新
本地指令。其他Superlane由硬件每行晚一拍传播，与回传后的行间相位匹配；
这不是前端计算指令的3拍传播。默认S启动计算，首条后端在S+23启动，
相较回传前整体后移4拍，累加器自身的控制/运算/访存流水不变。

以本列后端指令更新为L0：

| 时刻 | DIRECT_OUT | STORE | ACC_STORE | ACC_OUT |
|---|---|---|---|---|
| L1 | 控制前行 | 控制前行 | SRAM预读 | SRAM预读 |
| L2沿后 | 新部分和可用 | 新部分和可用 | 新A和旧B同时可用 | 同左 |
| L3 | 直通第1级 | 直通第1级 | A/B直接进入A1 | 同左 |
| L4 | 直通第2级 | 直通第2级 | A2 | A2 |
| L5 | 直通第3级、数据就绪 | 同左 | A3、结果就绪 | 同左 |
| L6 | 端口输出有效 | SRAM写入提交 | 原位写回提交 | 端口输出有效 |

以A1采样沿T表达：launch=T-3，读请求=T-2，A/B可用=T-1，
A1/A2/A3在T/T+1/T+2，写回或最终输出在T+3。
新部分和直接连接A1，没有用于等待SRAM的额外宽数据寄存器。
STORE复用三拍直通以保持与ACC_STORE相同写入相位；DIRECT_OUT也与
ACC_OUT共用输出完成相位。输出寄存级同时用于FP32直通和BF16转换。

| 可见约定 | 当前值 |
|---|---|
| 后端指令更新→预读服务 | 1拍 |
| 后端指令更新→A实际采样 | 3拍 |
| 后端指令更新→写入提交/输出 | 6拍 |
| 左端回传部分和可用→最终输出 | 4拍 |
| 顶部阵列部分和可用→最终输出 | ROWS+4拍，默认8拍 |
| SRAM读请求→ACC_STORE写入提交 | D=5拍 |
| 连续批次稳态II | 1 |

后端COUNT可与计算COUNT不同，但所有后端指令合起来必须恰好消费对应
的新部分和序列。允许一条COMPUTE32对应两条STORE16；地址和标签必须
按原顺序衔接。后端队列水平间隔为一拍，COUNT1也可连续每拍发射。

## 7. SRAM地址、依赖和段间Bank相位

每个输出列拥有两个单端口Bank。逻辑批次地址a映射到：

```text
bank = a % 2
row  = a / 2
```

编译器必须保证：

- 一个Bank在同一服务沿最多有一个请求，读和写合并计数。
- 旧值地址已初始化，且前一轮对该地址的写入已经提交。
- 不在同Bank写入提交沿同时读取，即使描述为“先写后读”也不合法。
- 四种操作统一检查base+实际COUNT<=DEPTH，不允许地址回绕；DIRECT_OUT
  地址也受此限制，仅为结果批次标识，不是最终输出目的地。地址宽度由DEPTH
  推导，包含最低位Bank号；公开监测口补零到16位。OUT_BF16只可用于两种
  输出指令，STORE/ACC_STORE必须保持FP32。
- 每条操作都按固定服务时刻核对，不能只根据“读写数据的序号交替”判断。

奇数D=5使持续交替访问的读和对应写回使用不同Bank，但段间从地址0
重新开始时，还要保证Bank相位。以同一地址区间连续处理B批为例：
STORE在L0启动，下一轮ACC_STORE在L0+B启动，则新轮读取地址base+i
的同一拍，旧轮写入地址base+j，交接重叠区有：

```text
j = B - 5 + i
```

在这里的连续、顺序、同址区间、无额外间隙条件下：B为偶数，两地址
奇偶性相反；B为奇数，两地址同Bank。例如32批交接时同时W27/R0，
33批则同时W28/R0。此公式不是任意跳转、空拍和地址序列的无冲突保证。
任意插入空拍都必须重新核对绝对服务沿，不能认为“多等一拍一定安全”。

## 8. 奇数有效批次的编译器补齐策略

此处的B表示一轮地址区间内的结果批次数，不是MATRIX_N输出列数。
对希望连续原位累加的地址区间，编译器区分有效批次数B_valid与物理
调度批次数B_sched，采用：

```text
B_valid > 0
B_sched = round_up(max(B_valid, COMPUTE_MIN_COUNT), 2)
```

例如33个有效结果按34批调度，34～39等偶数/奇数长度也分别保留或补齐；
少于32个有效结果仍须满足当前COMPUTE最小32批的物理输入要求。
更大阵列还需满足权重加载覆盖长度；本公式按当前默认MATRIX_N=32使用。

编译器负责生成填充activation的完整行输入、分配填充结果地址，且让
STORE/ACC_STORE的完整地址轮转覆盖B_sched。填充不是硬件自动发生的。
填充槽不参与有效输出，但仍要提供valid并满足SRAM先写后读、地址合法等规则。
不能依赖填充槽的最终浮点数值来判断它是否有效。

偶数要求针对连续原位累加的完整地址轮转长度，不要求每一条后端COUNT
都为偶数。多个指令可以分段覆盖同一个偶数长度区间；DIRECT_OUT等
不涉及上述读写交接的操作也不能一律禁止奇数COUNT。

### 最终有效输出与填充槽消费

当前ISA没有DROP指令、尾部有效数量字段或自动丢弃填充结果的掩码。
因此不能只把计算COUNT从33改成34，然后让后端只消费33批：第34批
仍会到达，缺少对应操作会报错。

对于已分配34个物理地址的累加区间，可用现有指令表达最终一轮：

```text
COMPUTE COUNT=34                     # 第34批为填充，输入仍需完整提供
ACC_OUT base=0, COUNT=33             # 输出33个有效结果
STORE   base=33, COUNT=1             # 连续消费填充批，只存入填充地址
```

两条后端指令按33/1批连续衔接，第二条STORE的格式位必须为0。
它只消耗本轮最后的填充部分和，不影响有效地址的累加结果。
该序列是编译器应实现并新增集成验证的策略示例，目前不是已经跑通的
编译器测试结果。也可由未来输出接口按有效长度过滤，但不能假定当前已有。

填充后的地址区间必须能放入SRAM，COUNT和地址必须能被ISA表示；不能
通过截断计数字段处理越界。规模超出时由编译器拆分成合法子区间。
有效批次数为0时不发射指令；后端数量编码0表示实际1批，不表示空任务。

## 9. 故障、复位与重新调度

非法指令、空队列发射、过早发射、缺少输入、后端多批/缺批、部分和标签
错位、未初始化读取、未提交地址重访或Bank冲突均不是合法调度。
当前RTL对已实现的检测条件置sticky fault，部分非法访问会被抑制；这不
意味着所有编译器违约都能被自动检测，也不保证报错后的其余结果有效。

`rst_n=0`清队列、流水valid和SRAM初始化有效位，不清SRAM数据阵列。
`run=0`取消在途执行并清fault，保留队列及SRAM已存数据/初始化状态；
前端weight有效位失效，重新计算前须重新加载。停止后不能接着旧流水
的中间位置运行，编译器/运行时必须重新安排被取消的工作。发生故障时，
保留下来的SRAM可能已有部分更新，不能仅清fault就假定整轮累加已完成。
