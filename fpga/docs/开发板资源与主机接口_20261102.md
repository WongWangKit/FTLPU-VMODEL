# LPU16 开发板资源与主机接口评估

## 选型结论

**已确认约束（2026-11-02 用户补充）：采购预算无上限。** 选型以保留完整 LPU16、实现余量、平台接口成熟度和开发周期为优先，不为板价主动裁剪 MEM/SRF 或运算格式。团队现有板卡库存仍未确认；compact 配置仅保留为快速验证备选。预算信息不改变当前整机资源尚未验证的状态。

**完整 LPU16 原型优先评估 HTG-960/VU19P；VCU118 Rev.2.0 或更新版本保留为现有板复用、模块测试与经过裁剪的演示候选。** 实测叶模块外推显示，MEM、SRF 和 VXM basic 的直接复制已超过 VCU118 的 LUT 总量，不能仅凭 SRAM 容量选板。VU19P 提供更充分的 LUT 余量，但 DSP 少于 VU9P，仍需完成 native MXM 和特殊函数单元的预算。暂不据此下单或承诺任何候选已通过整机装载。已有 U250 时也可作为优化后中间档候选；不建议为本项目新购 ZCU102。

本表是**芯片总资源和板载能力**，不是加入 DDR/PCIe/时钟/复位/ILA 后留给 LPU 的净资源。器件资源以本机 Vivado 2023.2 器件库和 AMD 数据表核对；接口以具体板卡手册为准。检索日期为 2026-11-02。

## HTG-960 的资源与主机接口取舍

厂家确认 VU19P、两个 72-bit ECC DDR4 插槽、六个 FMC+、80 条板上 FMC+ GTY、千兆以太网、USB-UART、JTAG、两颗 2 Gb QSPI 和 12 V/8 A 配套电源；**随板内存是 8 GB，64 GB 是插槽支持上限**。PCIe 需要另购附件并验证连接、参考时钟和驱动，不能按 VCU118 直插卡方案估算工作量。[HTG-960 官方页面](https://www.hitechglobal.com/Boards/VirtexUltraScale%2B_VU19P_Board.htm)

推荐先以以太网传输已量化权重/输入，UART 仅管控，JTAG 调试。量产式高吞吐演示再接 PCIe；厂家页面没有在该板产品条目中给出可直接承诺的 PCIe lane rate、DDR 持续带宽或交期，应向厂家索取具体套装 BOM、参考工程和报价。此候选的主要优势是 LUT，而非 DSP：不能认为 VU19P 的所有资源均多于 VU9P。

本机 2023.2 器件库包含 `xcvu19p-fsvb3824-2-e`。本轮综合实际目标仍为 VCU118/VU9P；未在 VU19P 上运行整机综合、实现或板测，VU19P 的具体许可需在后续构建时验证。

## VCU118 具体资源与限制

- 目标综合器件：`xcvu9p-flga2104-2L-e`，0.85 V 工作点；板上型号为 `XCVU9P-L2FLGA2104E`。早期 0.72 V 板和 ES 器件不能直接套用本次目标。
- BRAM36 原始位容量约 9.49 MiB，URAM 原始位容量 33.75 MiB，均含物理块位宽口径；实际有效数据容量受宽深配置、独立 bank 碎片和 ECC 影响。不能把两者简单相加后认为任意 SRAM 接口均能装入。
- 52 路封装可用 GTY；板上分配给 PCIe、QSFP、FMC+ 等。832 个器件 I/O 也不是 832 个空闲 GPIO。旧顶层数万位调试/流接口只能成为芯片内部连接，不能直接映射板针。
- 双 DDR4 为两组 5×x16 器件，即每路 80-bit 物理总线。建议按**每路 64-bit 数据、2 GiB 有效载荷容量**规划，ECC/剩余位按 MIG 实际配置确认；不将标称 5 GB 全部作为应用 payload。以 2400 MT/s、64-bit 数据计，理论峰值为每路 19.2 GB/s、两路 38.4 GB/s，不是实测可持续带宽。[UG1224，DDR4 Component Memory](https://docs.amd.com/api/khub/documents/Uoc4S9pQd1uve6kiGiG2kA/content)
- RLD3 和板上系统控制 Zynq 不作为第一阶段数据路径：额外控制器、接口和验证成本没有必要。系统控制 Zynq 不能未经核对就当作 LPU Linux 主机。
- Rev.2.0 及以后手册确认 Gen3 x16；早期板只有 Gen3 x8。本方案不把部分宣传图中的 Gen4 字样作为已验证可用模式。先用 Gen3 x8，编码后理论单向上限约 7.88 GB/s，TLP/DMA 实际吞吐还要扣开销。[UG1224，PCI Express](https://docs.amd.com/api/khub/documents/Uoc4S9pQd1uve6kiGiG2kA/content)
- VCU118 高度超过标准 PCIe 卡；确认机箱空间、转接线/开放式测试架、12 V 供电和散热。PCIe 主机建议使用团队熟悉的 Linux 环境；本机 Windows Vivado 的综合成功不代表主机驱动已打通。
- 官方产品页当日显示 **US$14,995、6 周交期**，只作预算量级参考，不作为报价或供货承诺。优先借板，采购前核对渠道、板卡版本和 Vivado 器件许可。[AMD VCU118 产品页](https://www.amd.com/en/products/adaptive-socs-and-fpgas/evaluation-boards/vcu118.html)

## 主机和存储实现路线

1. **最小闭环**：JTAG 下载 + UART 控制/状态 + BRAM 中的小输入；读写、run/idle/drain、错误状态和结果 CRC 先闭环。UART 不承担模型权重批量传输。
2. **标准演示接口**：VCU118 使用 PCIe XDMA → AXI-Lite CSR 与 AXI-MM DDR；HTG-960 首轮采用以太网 MAC/协议桥接，PCIe 附件验证后再选 XDMA。以太网 PHY 本身不是可直接使用的主机接口，MAC、协议、缓冲和主机程序仍需实现。AXI-Lite 用于版本、配置、start、done、fault、性能计数器，批量接口用于 schedule/权重/输入和结果。旧 `schedule_*` 与 `host_mem_*` 不是 AXI 接口，必须新增桥接和包格式。
3. **外存与静态日历隔离**：DDR/MIG 的可变延迟不能直接替换 native MEM 的固定一拍读契约。采用预取、双缓冲、明确 ready/fence 后再启动固定周期计算段；不足时停在段边界，不能临时插拍破坏流调度。
4. **时钟与复位**：LPU 初始目标 50 MHz，100 MHz 作为后续收敛目标；XDMA、MIG 和 LPU 之间使用明确 CDC/FIFO。执行复位保留 MEM，冷启动由 BRAM INIT 或显式清零流程保证；同步释放各时钟域复位。
5. **带宽校准**：CModel profile 中 `lpu_clock_mhz=500`、DDR `51200 MB/s` 和固定延迟参数属于模型假设，不能直接作为 FPGA 性能指标。先测 DMA、DDR 顺序访问及小块访问，再回填板级 profile。

## 采购或借板前的准入条件

- 固定 native MXM/VXM/SXM 的实际代码基线及 LPU16 端口几何，完成模块级综合；保留输出可观察性，检查黑盒和常量裁剪。
- 集成一次完整候选核心与至少一套 DDR/PCIe shell；建议规划 LUT、BRAM、DSP 均不高于约 70%，这一数值是工程余量策略而不是可布线保证。
- 50 MHz 完成布局布线、STA、CDC/复位检查，随后尝试 100 MHz。OOC 综合的正 slack 不能替代该门槛。
- 冻结演示范围及 host/FPGA 分工。未完成原生整机时，子模块演示应明确标为子模块或混合演示。
- 采购预算已确认无上限；仍需核对实物库存、板卡 revision、主机插槽、驱动环境、配套附件和交期后决定购买型号。
