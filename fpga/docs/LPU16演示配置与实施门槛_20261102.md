# LPU16 演示配置与实施门槛

## 推荐演示范围

第一阶段以 **16-lane 数据通路和 W8A16 矩阵计算的小闭环**为目标，随后演示 SmolLM2-135M 的单层 FFN；不把“完整语言模型生成”设为 native RTL 未齐阶段的首个交付。

配置决策仍为提案，本轮没有修改产品 profile、原始 RTL、ISA 或跨模块调度。

| 项目 | 首轮目标 | 扩展目标与条件 |
|---|---|---|
| 开发板 | 完整结构优先评估 HTG-960/VU19P；已有 VCU118 用于模块与受控裁剪验证 | 采购须有 native 核心 + shell 资源/实现结果 |
| LPU 几何 | 2 半球；2 tiles × 8 lanes；每半球 1 个目标 16×16 MXM | native MXM 参数化完成后确认实际实例数与接口，旧 RTL 是 4 个 32×32 MXM，不能替代 |
| MEM | 每半球 52 slices，双 bank，每 bank 每 tile 1024×64-bit，合计 3.25 MiB | 采用经验证的 FPGA BRAM 后端；若改容量/列数必须另建 demo profile，不覆盖正式 LPU16 |
| SRF | 16 columns、32 streams/direction、2 directions、lane-valid | 原有 one-hop/consume/collision 契约保持；不为了省面积退回 tile-valid |
| VXM | 保留 16 个逻辑 ALU 位置及路由；先验证 basic 操作 | Exp/Recip/Rsqrt 和 LUT 接口通过独立综合/精度验证后再接 SwiGLU |
| 权重/激活 | 最初 BF16 权重 + BF16 激活排除量化干扰；演示目标 INT8 对称权重 + BF16 激活；FP32 累加 | INT4、FP8 不进入首轮；W8 的 scale、zero-point=0、舍入/饱和及反量化位置单独冻结 |
| 时钟 | 50 MHz 初始目标 | 100 MHz 仅在实现后 STA 通过才宣称；不沿用 CModel 500 MHz |
| 主机 | 控制/预载/取回与核心计算分离；第一阶段先预载再 run | 真实 DMA/DDR 完成和缓冲所有权必须通过 fence/ready 协议，不给 native 固定日历添加随机停顿 |

## 分级用例与输入规模

### A 数据路径与基本算子

- MEM 写读、保留、非法地址/指令、reset 后 SRAM 保留；SRF 逐 lane 转发、consume、collision；VXM Add/Sub/Mul/Max/Negate。
- MXM 接入后，`M=1/16，K=N=16` 开始，再测 `K=N=64` 分块和跨 tile 输出。ReLU 用 Max(x,0)；transpose/permute 仅覆盖已完成并通过约束检查的路径。
- 用确定性全零、单位阵、正负交替、边界数、随机整数权重和不同地址映射；比较完整结果，不只比较最后一个状态位或 CRC。
- 这一级可称为 LPU16 算子演示，不能称为完整模型推理。

### B SmolLM2-135M 单层 FFN

模型原始维度为 hidden=576、intermediate=1536、30 层、9 个 attention heads、3 个 KV heads，使用 SiLU。首轮 **batch=1、单 token、只执行一层 FFN**，扩展到 16 个输入行。[HuggingFaceTB 官方配置](https://huggingface.co/HuggingFaceTB/SmolLM2-135M/blob/main/config.json)

FFN 为 gate/up/down 三次矩阵计算及 SwiGLU：`down(SiLU(gate(x)) * up(x))`。W8 权重原始数据为 `3×576×1536 = 2,654,208 B = 2.53125 MiB`；每输出通道一个 BF16 scale 另需 7296 B。单行 BF16 输入 1152 B。总字节数小于 3.25 MiB **不代表能按现有 slice 角色一次全部驻留**；仍需编译器检查权重 bank 分配、scratch、累加器和结果行边界，必要时从 DDR 分块换入。

旧 `smollm2_ffn` 回归可以借鉴 schedule/黄金值组织，但其代码使用小型确定性矩阵与旧顶层，不是原尺寸 135M 模型已上板的证据。禁止直接把旧 4-tile schedule 改个文件名当 2-tile 回归。

SiLU 若暂放主机，演示明确标为“主机 SiLU + FPGA GEMM 的混合 FFN”，结果同时给出算子耗时和端到端耗时；不能报告成全 FPGA FFN 性能。量化权重和校准数据尚未准备，模型准确率不得先填数值。

### C 完整生成演示

后续再加入 RMSNorm、QKV/attention、RoPE、Softmax、KV cache、残差、embedding 和输出头。输入先限 32-token prompt、最多生成 32 tokens、总上下文不超过 128；batch=1。

135M INT8 权重约 135 MB，另有 scale、部分 BF16 参数和缓冲。按上述模型的 3 KV heads、head_dim=64，BF16 KV cache 在 128 tokens 时为 `2×30×3×64×2×128 = 2,949,120 B`。这些容量对候选 DDR 都不构成主要困难；算子覆盖、调度正确性和权重流量才是前置工作。该阶段未在本轮执行。

## VCU118 上的配置调整建议

**不建议只减 SRAM 深度。** 实测资源表明，流选择器和逐 lane 运算单元的 LUT 才是更大的压力来源。

1. 优先保持完整正式 profile，在 FPGA 专用后端中修正 RAM 推导、采用适当 DSP 映射、移除没有功能的结构和仅用于仿真的超宽观察端口。接口语义、错误检测与运算结果不变才可称后端优化。
2. 固定 BF16 的 basic ALU 实验有面积下降，但仅减少数据格式并不足以证明完整 LPU16 能放入 VU9P。BF16 特殊函数可能仍内部用 FP32，不能按 16/32 位宽比例减半估算。
3. 如必须用现有 VCU118 先演示，建议另评估 `demo_lpu16_compact`：保持 16 lanes，MEM slices 从每侧 52 缩至 16、深度仍 1024、总 MEM 1 MiB，分组数 4、SRF 列数相应为 7。**这是横向拓扑、队列映射和软件布局均有变化的实验配置**，不是当前正式 LPU16；需要单独生成合法 profile、重编 schedule 和验收，不能仅向旧 top 传 `ACTIVE_MEM_COLUMNS=16`。
4. 该 compact 外推仍需加 MXM、特殊 ALU、SXM、ICU 和 shell，尚未实现。若加上这些后无足够余量，使用更大 FPGA；不靠屏蔽错误或减少输入可观察性制造“能放下”的结果。

## 上板交付门槛

| 阶段 | 可验收输出 | 当前状态 |
|---|---|---|

| Post-synthesis functional | 同一端口级 TB 分别运行 RTL 与综合网表；保存 FAIL 和 PASS | MEM BRAM 后端、SRF、basic ALU 已执行；不是整机仿真 |

| FPGA 平台集成 | 时钟复位、CDC、MIG、host bridge、DMA、约束、ILA | 未实施 |
| 实现与板测 | place/route、setup/hold、CDC、bitstream、真实板数据 | 未执行 |
| 模型演示 | 固定权重/scale/输入，算子与端到端耗时，正确性和准确率 | 本轮仅确定范围与资源规划 |

用户已确认采购预算无上限，因此完整 LPU16 为主线，compact profile 不作为成本约束下的默认选择。现有板卡库存、主机 OS、是否另做 compact 快速验证、SiLU 是否允许暂时放主机，仍需项目决策。已有 native 集成文档中延期的 MXM 跨模块问题不因本评估被自动修改。
