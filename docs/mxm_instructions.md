# 新版 MXM 指令与控制流

编译器、数据供应方和RTL共同遵守的外部时序/输入约束集中维护于
[MXM时序与输入调度约定](mxm_scheduling_contract.md)。本文件说明指令编码、
控制机制与验证示例；奇数批次补齐属于调度策略，不增加硬件COUNT奇偶限制。

## 实现边界

`lpu_mxm_frontend` 已连接独立计算/加载队列、纵向计数器控制器和
4×4 Supercell 阵列，输出每列的 FP32 部分和、事务标签及对应控制。
单列权重写入已实现。独立的 `lpu_mxm_backend` 已实现两个单端口 Bank
及四类后端操作，`lpu_mxm_core` 将它与阵列相连。后端是第三条独立队列，
不再通过计算指令控制访存。可选BF16输出已实现，输出端口选择及stream打包暂未实现。
旧 `lpu_top` 仍通过 legacy slice 运行旧 C 模型，不会静默解释新版指令。

## 指令编码

定义位于 `rtl/mxm/lpu_mxm_isa_pkg.sv`，为新的 64-bit 编码。
`instruction_t` 的字段布局如下；不兼容旧 48-bit IW/Block8 编码。

| 位域 | 字段 | 含义 |
|---|---|---|
| 63 | version | 必须为 1 |
| 62:57 | column_index | COLUMN 的目标输出列，默认 0～31 |
| 56:51 | weight_stream | 加载指令的行内输入流绑定 |
| 50:45 | reserved_output | 必须为零，输出属于后端 |
| 44:39 | activation_stream | 计算指令的行内 activation 流绑定 |
| 38:19 | reserved_backend | 必须为零，访存和累加由独立指令控制 |
| 18:3 | count | 计算的输入向量个数，不是累加器存储容量 |
| 2 | weight_buffer | 使用/加载的权重 Buffer |
| 1:0 | opcode | 0=MATRIX，1=COLUMN，2=COMPUTE，3=非法 |

COMPUTE 要求 COUNT 为 32～65535，column_index/weight_stream 及上述保留位
为零。计算 COUNT 不再受累加器容量限制，不包含累加地址或结果路由。
MATRIX/COLUMN 要求 COUNT、activation_stream 及保留位为零。
MATRIX 的 column_index 为零；COLUMN 必须位于实际 MATRIX_N 范围内。
硬件拒绝非法队首命令并置 fault，不启动计算/加载。

activation/weight 流绑定字段随命令传播，供外部流选择器使用。前端数据接口直接接收
每行已经选好的 CELL_K 个 BF16，不在本模块内解释旧版 64-bit stream
打包格式。输出以 FP32 列接口交给独立后端。

## 后端独立指令

`lpu_mxm_backend_isa_pkg.sv` 定义独立 64-bit 编码：bit63=1，
bit62:35 保留为零，bit34 为 OUT_BF16，bit33:18 为 COUNT，bit17:2 为逻辑起始地址，
bit1:0 分别编码 0=DIRECT_OUT、1=STORE、2=ACC_STORE、3=ACC_OUT。
COUNT 为 1～65535，是本条后端指令处理的批次数，与计算指令 COUNT
相互独立；例如一条 COUNT=32 的计算可以由两条 COUNT=16 的 STORE 消费。
有访存的指令要求 base+COUNT 不超过逻辑深度。OUT_BF16只对DIRECT_OUT和
ACC_OUT有效：0输出FP32，1输出BF16；STORE/ACC_STORE必须为零，违规报错。
输出位置尚未编码。两种格式共用一级输出寄存器，统一 launch+6 输出，II=1。
BF16按RNE转换并保留非正规数；核心32bit lane的低16位承载BF16，
高16位为零，result_bf16_o随有效位/地址/标签同步，不在此处定义stream打包。

后端队列使用同样的显式 enqueue/launch 协议。命令沿水平方向每列
晚一拍，匹配阵列结果的列间相位；不采用计算层间的三拍延迟。
每列按顺序消费新部分和，不能跳过、重复或自动等待数据。

## 独立队列与发射

计算、权重加载分别配置一条深度为 INSTRUCTION_QUEUE_DEPTH 的 FIFO。
两条队列可同时入队和运行，预装指令时 run 可以为零。
enqueue valid/ready 握手只表示入队；不会自动启动队首指令。
编译器在准确时刻产生对应的 launch 脉冲。

launch_ready 表示队首存在、底层执行可结束且旧指令可以交给紧邻上层，
不是数据 backpressure。空队列、过早或非法发射都会置 sticky fault；
过早发射不出队、不自动重试，必须另发 launch。
入队在满队列时由 ready 拒绝；同拍出队与入队可以复用腾出的槽位。

## 各层本地计数器控制纵向接力

计算和加载指令流分别在各个非最顶层 Superlane 设置一个本地转发
计数器。只有本层指令被替换时才重新开始计时，三拍后将该指令
交给紧邻上层，随后停止计时；上层从接收时刻开始自己的三拍计时。
每层保存自己的当前指令、原始持续时间及待转发标志。
最顶层没有转发计数器。没有全局时钟计数器、转发时刻或整链忙标志。
这些本地三拍计时与数据 COUNT 执行计数分开。
底层在 E0 接收命令，各层依次在 E0、E3、E6、E9 更新执行指令。
每次仅使能目标层，不会把其他层仍在执行的旧指令重复启动。
各层在自己的有效周期内每拍消费一个输入，COUNT 个周期后结束。
每行的剩余拍数/数据索引是执行计数，不是额外的纵向传播计数器。

发射沿 E0 后底层 valid 可用，数据由 Supercell 在 E1 第一次采样。
COUNT=32 时，下一条可在 E32 无空拍替换底层，上层分别在 E35、E38、E41
替换。旧指令在各层恰好完成自己的 32 拍，不受底层提前切换影响。
流水中的结果继续携带旧指令的地址和控制，直到输出。

不等待整条链传播完成：本层在三拍后把旧指令交给紧邻上层，
就可以在本地执行完成后替换。上层自己保存并继续转发旧指令，
不同层可以同时持有不同指令。交接与替换可以在同一时钟沿发生，
接收方采样的是前一层的旧指令，随后前一层更新为新指令。

多层时，同一队列的最小发射间隔为 max(本地执行拍数, 3)，
不随层数增加；单层时只取决于本地执行拍数。
计算最少 32 拍，MATRIX 为 32 拍，均自然超过三拍。
COLUMN 本地执行一拍，当前每层只保存一个待转发命令，因此同一
加载队列的发射间隔至少三拍，而不是等到最顶层执行或接收完成。
例如两个 COLUMN 分别在 E0、E4 启动，各层接收时刻分别为
(0,3,6,9) 与 (4,7,10,13)，两条指令的传播可以重叠。
该控制器对加载也使用三拍层间相位；各行的权重数据必须跟随对应相位。
一拍 COLUMN 指每个 Superlane 本地的一拍，不是四行同一全局拍同时写入。

## 权重加载

权重数学形状为 W[K][N]。一组输入的 32 个 BF16 对应一列 W[:,n]，
分成四行各 8 个 BF16，每行本地拍宽度为 128 bit。
MATRIX 每行持续 MATRIX_N 拍，COLUMN 每行持续一拍；默认分别为 32 和 1。
MATRIX 稳态四行并行输入时总带宽为 512 bit/拍，起止保留层间相位差。

MATRIX 输入全局列序 MATRIX_N-1 到0，右侧块先装入。每个Supercell将
旧尾部、valid、buffer ID一起寄存，下一拍由右邻居写入，与activation的
每级一拍推进一致。每行入口仍输入32拍；SC c最后一拍写入比左端晚c拍，
对应activation也晚c拍，不需要等待整行权重全部完成才启动左端计算。
每个单元只保护自己的M1采样沿；默认COUNT32即可连续交替加载B0/B1，
计算与权重替换均不需要原来的整行3拍保护间隔。

COLUMN命令的数据、地址和buffer ID作为单拍包逐单元寄存传递，在
Supercell列号column_index/CELL_N处更新组号column_index%CELL_N，
其他权重保持，不触发权重内容移位。目标SC c在本行入口采样后c拍更新。
MATRIX尾部和COLUMN包独立推进，紧邻交接也不丢尾部；实际同端口冲突报错。
每行的加载持续周期内必须有输入数据，缺拍报错，不延长命令。

## 结果与 SRAM 预读时序

当前九拍点积、三拍向上合并。默认四层时，底层命令在 E0 启动，
第一个向量在最顶层四列的结果分别于 E21、E22、E23、E24 可用。
每列的一批 8 个 FP32 同时有效，各列保持一拍偏移。
后续结果每拍一批；COUNT 只控制发起次数，不缩短结果排空时间。

前端只传递计算指令和事务标签，不再发 SRAM 预读请求。
编译器以A/B会合并由加法器A1采样的沿T为基准倒推：T-3发射后端指令，
T-2预读SRAM，T-1沿后旧值B与阵列新部分和A都可用，T直接进入A1，
T+1/T+2经过A2/A3，T+3写回或经过共同输出级输出FP32/BF16。
因此后端launch比阵列结果可用沿提前2拍；新部分和不经过等待SRAM的寄存器。
从阵列结果可用沿到最终输出为4拍，从后端launch到输出为6拍。
相对launch，读请求固定L1、所有写入固定L6，读到原位写回仍为5拍。
首次读/写请求的偏移现在分别固定，不再用延迟A来凑成相同的偏移。
窄控制提前两级传递，到L3与A一起生效。DIRECT_OUT/STORE复用三拍直通
流水，不做加法；STORE与ACC_STORE同相位写入，以保持各种交接的Bank相位。
所有操作在L3直接消费A，连续指令不因操作不同而漏批或争用输入。
详见 [mxm_accumulator.md](mxm_accumulator.md)。

## 复位与验证

复位清空两条队列、所有执行/传播状态、标签及流水 valid。
run=0 取消正在执行和传播的命令并排空 valid，但保留已排队命令；
重新开始后需要编译器重新安排被取消的工作。前端同时使权重有效位失效，
重新计算前需要加载权重。没有动态 stall、重试或反馈寄存器。

运行 `python scripts/test_mxm_supercell.py`。
控制器黑盒测试覆盖 1/2/4 层、深度 1/3 队列、32/40/32 连续计算、
间隔 3/4/5 拍的多条单列指令重叠传播、本地计时重新启动、
整块与单列加载、满队列同拍入出、计数/标签、非法和过早发射、复位。
4×4 阵列黑盒测试比对 104 个向量共 3328 个 FP32 结果，覆盖两套权重、
单列修改不影响其他列、边算边加载及跨指令标签/控制。
后端测试覆盖三种列数/并行路数、四种操作全部 16 种交接、576 批连续
输入、Bank 请求和 A/B 源数据、数值舍入、1022/1023 末地址、非法/冲突/
未初始化/过早重访/缺数据及复位。完整核心测试由四条计算、五条后端
命令驱动，验证 4096 个阵列部分和、2048 个最终输出。

### 完整核心的紧凑发射与数据依赖

完整核心测试以首条权重加载的实际发射沿为统一 E0，不以入队沿或各图
各自的首次事件为时间原点。三条指令流必须分别观察：

| 指令流 | 连续更换四套权重的发射沿 | 操作 |
|---|---|---|
| 前端权重加载 | E0、E32、E64、E96 | 四套不同权重依次写入B0、B1、B0、B1 |
| 前端计算 | E32、E64、E96、E128 | 各32批，B0、B1、B0、B1 |
| 后端累加与存储 | E51、E67、E83、E115、E147 | STORE16、STORE16、ACC_STORE32、ACC_OUT32、DIRECT_OUT32 |

前端指令发射后，底层从下一沿开始实际消费输入。B0 的32拍权重在 E1–E32
写入，首条计算在 E32 发射、E33 才读权重；不能把 E32 的指令有效理解为
E32 已经使用权重。B1 在 E33–E64 加载，与 B0 计算重叠，E65 开始用于
第二条计算。第三、四套权重分别在E65–E96、E97–E128输入，每次计算32批，
持续更换权重时也无空拍。四层输入沿均按3拍错开，不必等最顶层加载完才
启动底层计算。四列首批部分和在E53–E56到达，随后各连续128批。

底层SC0/1/2/3最后一次使用旧B0分别在E64/65/66/67，新权重写入分别从
E65/66/67/68开始，于E96/97/98/99完成，E97/98/99/100开始下一轮计算。
只比本地最后采样晚一拍即可，寄存的权重链接保证右侧不被左侧提前覆盖。
测试通过公开端口逐单元检查所有16个SC的实际写入、计算窗口和buffer ID。
40批activation场景计算在E32/72/112/152启动，权重在E0/32/72/112启动，
每次权重仍只有32拍，计算连续160批；加载端口可以有空闲，计算不需要空拍。

两个负例分别将首次计算从E32提前至E31，以及故意在正常连续计算中插入
3拍但不调整Bank相位，验证真实核心分别在E32/E119报错。此3拍不是正常
重载所需的间隙。后端发射晚一拍的额外负例在
E54报错，确认硬件不会把新部分和缓存起来等控制。合法测试逐拍核对数值、
标签、输入接收、前端权重依赖、实际 Bank 请求和写回；每组各验证4096个
部分和、2048个最终输出。核心公开监测口直接连接后端真实 slot 与 Bank
接口，无测试专用数据旁路。

上述launch与SRAM周期不随输出格式改变；提前预读并去掉A等待级后，连续复用测试
四列首次最终输出均为E121/122/123/124；40批场景为E137/138/139/140。
例如E83发射ACC_STORE，E84预读地址0，E85的阵列结果与SRAM旧值都准备好，
E86在A1同拍采样，E87/A2、E88/A3，E89提交写回。整核逐lane核对A入口
等于本沿新部分和、B等于该地址旧值，以及地址和标签匹配；没有用延迟A来对齐。
核心另外两组合法场景分别覆盖连续的 ACC_OUT(BF16)→DIRECT_OUT(FP32)
和 ACC_OUT(FP32)→DIRECT_OUT(BF16)，逐拍验证无空拍、无重叠及格式元数据。
后端576批回归混合两种格式，并继续逐拍验证所有原始FP32写回。
额外17条COUNT=1的输出命令逐拍发射，覆盖
{DIRECT_FP32、DIRECT_BF16、ACC_FP32、ACC_BF16}的全部16种相邻交接，
地址、标签与新部分和由测试台独立安排，不根据DUT的slot有效位生成数据；
验证预读控制中同时存在多条不同指令时仍无空拍、错批及格式错位。
输出级独立回归遍历全部65536个保留高位编码，每个取5种舍弃低位，
另加4096个随机FP32模式，共331776个输入；每个输入分别检查FP32/BF16，
3路共核对1990656个lane结果，包含RNE奇偶中点、次正规/正规边界、
进位、溢出、正负零、Inf、NaN、连续格式切换、空拍和复位。

控制器单元测试独立检验两队列的传播，未连接权重存储和算术单元。
其中同时发射加载和计算仅是控制激励，不能作为合法数据调度的证据。
报告将其置于附录，并让同次控制单测的计算图与权重图共用同一时间原点。

实测波形可以用 `python scripts/plot_mxm_timing.py --simulate` 重新生成。
测试台在每个上升沿后 2 ns 采样公开端口，导出 CSV，并同时导出 VCD；
绘图脚本只使用这些实际采样值，不用期望数组绘制信号。
报告包括连续计算、单列指令重叠接力、阵列首批结果、实际双 Bank
读算写和完整核心输出；Bank 请求按实际服务沿记录，不以寄存器更新后的
请求代替已经发生的访问。
原始数据、仿真 PASS 日志、测量时刻及源文件 SHA256 一起保存供核对。
