# MXM 时序与输入调度约定

修订：0.5。日期：2026-11-10。适用于新版 `lpu_mxm_core`，不适用于旧legacy MXM。
本文件由硬件、编译器和验证共同维护；修改固定延迟、端口、地址或指令语义时须同步更新。
它不是自动执行的编译器检查器，文档约定不等于RTL已替编译器检查了整轮调度。

## 职责与粒度

| 内容 | 定义/责任 |
|---|---|
| 算术 | BF16输入DAZ，64位统一对阶CSA点积，FP32部分和与累加存储 |
| 默认阵列 | 4行×4列Supercell，每个8×8，完整逻辑activation为32个BF16 |
| 每列一批结果 | CELL_N=8个同拍FP32；四列合计32个，列间各晚一拍 |
| 回传 | 顶部列c下降至底起行c再向左，各路径默认4拍；交叉点有独立数据流 |
| 累加器 | 左端每个Superlane一套8路FP32加法器、两个512×256bit单端口Bank |
| 三条指令字 | 计算7位，加载8位，后端默认13位，均无COUNT字段 |
| 最小计算粒度 | 编译器安排至少32批的连续计算，配置常量COMPUTE_MIN_BATCHES=32 |
| 偶数轮转 | 连续原位累加采用偶数长度完整地址轮转，并保持时钟相位 |

“批次数B”是编译器对一段连续数据的规划，不是K维元素数、输出lane数或指令字段。
去掉COUNT只移除了硬件重复展开及其检查，没有取消32批最小粒度、换权重带宽和Bank规则。
没有旧10位长度上限；每个实际SRAM地址仍受DEPTH限制。

## 指令和数据供应

指令位域见 [mxm_instructions.md](mxm_instructions.md)，算术见
[mxm_supercell.md](mxm_supercell.md)，累加器见 [mxm_accumulator.md](mxm_accumulator.md)。

- 计算、加载、后端各有独立FIFO和launch。编译器提前入队，再按确定时刻发射。
- 每次计算launch负责一拍activation；每次后端launch负责一拍部分和及其实际地址。
  相同内容连续出现仍需要每拍有效发射，不以内容变化触发执行。
- 编译器用连续发射实现至少32批的计算组；RTL没有组长、组结束或32批计数器。
- launch=0是空拍，硬件传播对应valid=0。空拍不会延长或自动恢复其他事务。
- MATRIX加载一条命令固定消费MATRIX_N拍，COLUMN固定一拍；这部分固定模式控制保留。
- 在每行有效槽的采样沿前提供完整CELL_K个BF16和valid；缺少输入不会导致自动等待。
- 未用K项的activation和weight同时补零；不能靠少送lane或省略valid表达小矩阵。
- 上游按对应行命令的stream字段选好数据，本模块不解释旧64位stream打包格式。
- 后端全部有效操作必须与新部分和一一对应，不能重复、遗漏或错相位。
- 后端地址逐拍由编译器提供；顺序0～31就是32个明确地址，不是base+内部index。

入队握手只写FIFO；空队列同沿enqueue不能立即launch它。满队列允许同沿出队/入队。
数据路径没有ready/backpressure、动态停顿、自动重试或累加结果反馈旁路。

## 固定寄存器传播

前端每个相邻Superlane之间为3拍：发送端本地寄存器、中继1、中继2、接收端本地寄存器
分别在E0/E1/E2/E3体现同一有效操作。计算和加载各有独立指令/有效位流水。
中继不会等待一条指令到顶，也没有本地三拍计时器；可每拍传递不同或完全相同的字。
后端Superlane之间为1拍，与回传数据相位一致，不能也插入前端的两级额外中继。
标签为独立16位硬件事务序号，每接受一拍计算加1，随对应操作传播并允许回绕。
标签不代替编译器逻辑地址，不是已删除的指令内批次index。

## 阵列和权重时序

所有周期为同一时钟上升沿；“可用”指沿后已稳定，“采样”指该沿接收先前稳定的数据。
底层计算在S发射、行r从底起、列c从左起：

| 事件 | 时刻 |
|---|---|
| 行r计算指令有效 | S+3r沿后 |
| 单元(r,c)采样activation | S+3r+1+c |
| 本地点积可用 | S+3r+9+c沿后 |
| 上行合并结果可用 | S+3r+12+c沿后 |
| 默认四行顶部列c结果可用 | S+21+c沿后 |
| 左端Superlane c结果可用 | S+25+c沿后 |

activation在每个Supercell内广播给全部输出组，横向每级晚一拍；部分和向上加法固定3拍。
本地点积和下方部分和必须同拍、同标签到达；底层加零也经过相同三拍。

MATRIX每行输入按全局输出列MATRIX_N−1至0，共MATRIX_N拍；COLUMN执行一次相同移位。
数据、valid、buffer ID在单元边界共同寄存，结束命令不清在途尾部；两Buffer独立移位。
单次COLUMN不能填满空Buffer；必须送足完整列序列。
MATRIX在W发射：行r首拍采样W+3r+1，单元(r,c)末拍写入W+3r+MATRIX_N+c。
对应计算需满足S>=W+MATRIX_N。不可在同一单元M1沿覆盖正在使用的Buffer。
每个单元只保护本地M1采样沿，其后算术流水不再占用权重寄存器。
硬件ready只表示各组写过，不表示一套新版本矩阵完整，不可据此省略编译器依赖。

默认连续32批安排如下，表中是左端实际输入采样沿：

| 周期 | activation | 同时输入权重 |
|---|---|---|
| E1～32 | 尚未开始 | 第一套B0 |
| E33～64 | 使用第一套B0 | 第一套B1 |
| E65～96 | 使用第一套B1 | 下一套B0 |
| E97～128 | 使用下一套B0 | 下一套B1 |

SC c最后使用旧B0在E64+c，新权重从E65+c写入、E96+c完成、E97+c用于新计算，无全行保护空拍。
默认32拍最小计算组可覆盖32拍换权重；参数改变时，还需满足隐藏加载的带宽条件B>=MATRIX_N。
计算组长40时权重入口可空闲8拍，activation与阵列结果仍可连续。
固定MATRIX未结束时不得发射下一条加载；最后输入拍可更新下一条。COLUMN可以逐拍发射。

## 后端从会合时刻倒推

左端SL0某批新部分和在P沿后可用，则对应后端操作必须在P−2发射。
相邻Superlane由硬件晚一拍；它们使用同一操作和地址序列。
以本列一拍后端发射为L0：

| 时刻 | DIRECT_OUT | STORE | ACC_STORE | ACC_OUT |
|---|---|---|---|---|
| L1 | 控制前行 | 控制前行 | SRAM预读 | SRAM预读 |
| L2沿后 | 新部分和可用 | 同左 | 新A和旧B同时可用 | 同左 |
| L3 | 直通1 | 直通1 | A1采样A/B | A1 |
| L4 | 直通2 | 直通2 | A2 | A2 |
| L5 | 直通3完成 | 同左 | A3完成 | A3完成 |
| L6 | 输出 | SRAM提交 | 原位写回提交 | 输出 |

即T=A1采样沿时，launch=T−3、读=T−2、A/B可用=T−1、写回/输出=T+3。
新A直接进入A1，没有等待SRAM的宽数据寄存器。输出FP32与BF16共用一级寄存器，
二者均launch+6，BF16为RNE且不FTZ。最终stream打包和目的地尚未定义。
初次写入与累加写回均launch+6；SRAM读launch+1，读到写D=5。

## SRAM地址、依赖与Bank相位

逻辑地址a映射为bank=a%2、bank_row=a/2；一批8个FP32一起读写，结果回原Bank原地址。
每个Bank每沿只能读或写一次。编译器必须保证：

- 每拍address<DEPTH；默认0～1023。DIRECT_OUT地址也受限，作为批次标识，不是输出目的地。
- STORE/ACC_STORE不能设置BF16格式；仅两类输出允许量化，SRAM与累加始终FP32。
- 读取地址已初始化，且此前写入已提交；没有数据反馈/旁路修复过早读取。
- 写回与新读的Bank不相同；不在待写回地址上提前读或覆盖。
- 保持完整轮转的时钟相位，不能任意插入空拍后仍假定原来的无冲突结论成立。

连续交替地址下，D=5为奇数使读和对应写回落到不同Bank。
但首轮STORE与下一轮ACC_STORE的边界仍有条件：两轮同址区间各B批、无间隙，
同时被服务的旧写地址base+j和新读地址base+i满足 `j=i+B−5`。
B偶数则二者奇偶性相反；B奇数则相同。32批时同沿W27/R0，33批时W28/R0。
所以连续原位累加的一轮必须安排偶数批，并满足提交依赖；不能由“没有COUNT”推断无需该约定。
这不是任意地址序列/空拍的无冲突保证；RTL保留实际Bank冲突和待写回地址检测。

## 奇数有效批次与填充

编译器区分有效批数B_valid和物理调度批数B_sched：

```text
B_sched = round_up(max(B_valid, COMPUTE_MIN_BATCHES), 2)
```

例如33批有效结果可调度34批。编译器构造额外的完整零activation，分配填充地址33，
并让每轮存储/累加覆盖34个地址；不能只多发一个空操作或少送数据。
最后一轮可按下列编译器伪代码逐拍发射，循环不是指令字段或硬件重复器：

```text
for i in 0..33: emit COMPUTE(stream, buffer)     # 第33号为填充activation
for i in 0..32: emit ACC_OUT(address=i, format)  # 按预读相位发射
emit STORE(address=33, out_bf16=0)               # 消费填充批，不输出
```

每次emit的实际周期由固定流水安排，两条流从各自正确起点连续推进，不能按伪代码文本先后执行。
偶数约束针对完整地址轮转，不针对每条单拍操作；直接输出等没有上述交接的情况不一律禁奇数批。
规模超出SRAM容量需分配/拆分合法地址区间；无有效任务时不发射，不存在编码为零的空长度指令。

## 故障、恢复及验证范围

空队列发射、过早固定加载、缺输入、标签不对齐、未初始化读、待写回地址重访、Bank冲突置sticky fault。
这不代表编译器32批/偶数轮转已有硬件组长检查。run=0清在途和fault、保留队列及已存内容；
reset还清队列及初始化状态。部分写入可能已提交，恢复要重新安排完整依赖，不能只清fault继续。

| 场景 | 证据 |
|---|---|
| 连续相同字、空拍、3拍相位、满队列同拍出入 | 1/2/4行与深度1/3控制单测 |
| 全部前端字、标签回绕 | 384编码，66048拍，264192逐行检查 |
| 权重混合加载及纯COLUMN | MATRIX后两次移位；64条COLUMN按间隔3和1分别填充两Buffer |
| 后端16种操作交接、格式交接、地址和D=5 | 576拍混合数值及17拍连续输出单测 |
| 深度相关地址与非法编码 | 六种深度全部原始后端字，末地址实际读写 |
| 完整MXM连续换权重 | 32/40/1024批编译器刺激、部分和、回传、累加、格式及每个单元采样沿 |
| 奇偶边界 | 33批连续原位累加报预期冲突，34批完整轮转通过 |
| 自动补零与丢弃填充的真实编译器流程 | 尚未接入；上述伪代码是共同约定 |
| 物理宏/布线时序、最终stream打包与目的地 | 尚未实现/验证 |
