# MXM 累加器架构约定

外部发射/采样时刻、数据供应责任、Bank相位与奇数批次补齐策略见
[MXM时序与输入调度约定](mxm_scheduling_contract.md)。本文件说明累加器的
存储结构与实现；补齐由编译器安排，硬件不自动填充或丢弃结果。

本文件记录 2026-10-29 确定的方案。对应属性写入
`rtl/mxm/lpu_mxm_config_pkg.sv`。逻辑 Bank、FP32 累加及独立后端队列
已由 `lpu_mxm_backend` 实现，并在 `lpu_mxm_core` 中接入阵列。
旧 `lpu_top` 的 stream 网络尚未迁移，物理 SRAM 宏映射也尚未验证。

## 计算与存储粒度

一列竖向 Supercell 最顶部的 `CELL_N` 个 FP32 结果构成一批，
同时到达，同时进入对应的 `CELL_N` 路 FP32 加法器。
每组结果独立配置两个单端口逻辑 SRAM Bank，一个地址保存完整一批。
完整核心的顶部结果先经过固定向下/向左回传：列c送到Superlane c左端，
对应累加器也放在该左端。相邻Superlane保留一拍相位差，各自从Bank0开始。
回传仅增加等长寄存链，不修改本文件中的加法、Bank、地址或后端ISA。
下文“列”仍表示原顶部列对应的逻辑结果组，物理位置是回传后的Superlane。

默认组织为：

| 属性 | 默认值 |
|---|---|
| 列数 | 4 |
| 每列并行累加路数 | 8 |
| 每列 Bank 数 | 2 |
| 每个 Bank 的逻辑宽度 | 8 × 32 = 256 bit |
| 每列逻辑批次深度 | 1024 |
| 每个 Bank 深度 | 512 |
| 每列容量 | 32 KiB |
| 整个 MXM 容量 | 128 KiB |

宽度由 `CELL_N × ACCUMULATOR_BITS` 推导，256 bit 不是固定上限。
两个 Bank 平分逻辑深度，因此当前配置要求深度为不小于 2 的偶数。
不存在额外的第三个周转 Bank。

256 bit 是逻辑接口宽度。物理实现可使用一个宽宏，或在封装内并联
多个窄宏，共用地址和控制，拼接数据。必须配置具体 SRAM 宏映射，
不能假定 EDA 会自动将任意 RTL 数组映射为 SRAM。
如果实际宏延迟不同，需要更新封装流水、固定延迟及编译器调度。

## 地址交织与原位更新

对每列的逻辑批次地址 `a`：

* Bank 编号为 `a % 2`，即地址最低位。
* Bank 内地址为 `a / 2`，即去掉最低位后的地址。
* 一批中的所有 FP32 元素一起访问；计算结果写回原 Bank、原地址。

连续批次按 Bank0、Bank1 交替读取，不按结果通道编号交织。
每个 Bank 在一个服务时钟沿只能读或者写。

## 固定流水约定

| 时钟沿 | 对同一批数据的操作 |
|---|---|
| E0 | 读请求被接收 |
| E1 | SRAM 读数据可用 |
| E2 | FP32 加法器 A1 采样 |
| E3 | A2 采样 |
| E4 | A3 输出结果，送入写回路径 |
| E5 | SRAM 接收写入并提交原地址更新 |

读一拍、加法三拍、写一拍，得到读请求接收到写入提交间隔
`D = 1 + 3 + 1 = 5`，已在实际 Bank 服务沿逐拍验证。
这不是物理宏的测量结果。写回不能额外插入未计入 D 的寄存级。
Bank 的读捕获发生在 E0，占用一次单端口；输出寄存器在 E1 公布数据，
不再次占用 SRAM 端口。其他读写仍可每拍连续服务。

## 独立后端队列和统一请求时序

队列只包含 DIRECT_OUT、STORE、ACC_STORE、ACC_OUT 四种操作，
每条描述起始地址和连续批次数。计算指令不再包含累加或输出字段。
编译器提前入队，在预计的新部分和到达时刻按计划 launch；
不允许硬件自动推迟以等待数据或规避冲突。

| 相对 launch | 所有操作的共同阶段及分支 |
|---|---|
| L0 | 本列接收提前发射的后端指令 |
| L1 | ACC_STORE/ACC_OUT 预读 SRAM；其余指令仅传递控制 |
| L2 | SRAM 旧值 B 和左端回传部分和 A 同时可用；仅控制进入对齐级 |
| L3 | A/B 直接由加法器 A1 采样；STORE/DIRECT_OUT 进入旁路第一级 |
| L4/L5 | 加法器 A2/A3，或等长旁路第二/三级 |
| L6 | STORE/ACC_STORE 提交写入；DIRECT_OUT/ACC_OUT 输出 FP32/BF16 |

以加法器A1实际采样沿T倒推：T-3发射后端指令，T-2接受读请求，
T-1公布B；左端回传A也在T-1沿后可用，T同拍采样A/B，T+1/T+2经过
A2/A3，T+3提交写回或共同输出。左端回传部分和到端口后4拍输出；默认
顶部结果需先经过4拍回传，因此顶部到输出为8拍。
已移除intake_data/read1_a/aligned_a三组等待寄存器；只提前传递
操作类型、地址和格式等窄控制，不缓存A等待SRAM。所有操作都在L3消费A。

读请求固定launch+1，所有写入固定launch+6，读到写回仍为5拍。
两类访存的发射偏移分别固定，不再用延迟A来强行统一首次读/写请求时间。
编译器从A/B会合时刻倒推，四种操作的后端launch均比左端回传结果可用沿提前2拍，
所以COUNT与各条指令的交接仍可连续，无需按操作类型插入空拍。
后端在相邻Superlane复制同一操作序列、整体晚一拍，配合回传后的结果相位。
DIRECT_OUT 的寄存器旁路仅转发新部分和，绝不从 SRAM 绕过加法器输出。
STORE复用同一三拍旁路，不做浮点加法。其写入相位与ACC_STORE相同，
这样STORE→累加的预读、累加→STORE的尾部写回都保持正确Bank相位；
这三拍是既有直通/写回通路，不是插在A1之前等待读取的寄存器。

从本列第一次读请求开始编号，连续读取时：

| 周期 | 读请求 | 写入提交 |
|---|---|---|
| 0 | Bank0，第 0 批 | — |
| 1 | Bank1，第 1 批 | — |
| 2 | Bank0，第 2 批 | — |
| 3 | Bank1，第 3 批 | — |
| 4 | Bank0，第 4 批 | — |
| 5 | Bank1，第 5 批 | Bank0，第 0 批 |
| 6 | Bank0，第 6 批 | Bank1，第 1 批 |

奇数 D 使上述交替访问在每拍分别读取、写入不同 Bank，达到每拍一批。
同一批中的各路固定并行处理，不需要把 8 个元素拆成 8 拍。

## 编译器与控制约束

* Bank 相位跟随时钟，而不是只统计有效请求次数。空拍、跳转和新段
  起始都必须满足该相位；任意插入空拍后继续逐请求轮换并不保证无冲突。
* SRAM 操作数 B 按固定阶段读取，与寄存的新部分和 A 在加法入口对齐。
* 同一地址再次读取前必须完成之前的写回。没有旁路时，不能在同一
  Bank 的写回沿同时读取它；端口无冲突也不代表不存在旧数据依赖。
* 直接点积写入、首次结果初始化、累加写回和输出请求均由编译器安排，
  不允许覆盖已安排的单端口操作。直接写入可以发生在调度允许的空闲时隙。
* 地址、Bank、目的地、写使能和标签必须与数据一起按固定延迟传播。
* 不依靠本地动态重试解决调度错误。硬件已检测同 Bank 双请求、未初始化
  读取、尚未写回的地址重访/覆盖和缺少部分和，置 sticky fault 并抑制非法访问。

## 数据路径和待定项目

配置固定 `ACCUMULATOR_FEEDBACK_ENABLED = 0`：不设置累加结果反馈寄存器，
也不设置结果到操作数的转发旁路。新点积可送操作数 A、直接写 SRAM
或直接输出。操作数 B 只接 SRAM 读数据，不设反馈或零输入来源。
SRAM 读数据不直接送输出。累加结果可写 SRAM 或输出。
首次结果绕过加法器写入。

以连续处理 32 行的分块运算为例，每拍输入一行 32 个 activation，
各列依次处理对应的逻辑批次地址 0～31。首个 K 分块的结果直接存储；
后续 K 分块读取旧值，与新点积相加后原位写回。同一地址重访间隔为
32 拍，超过 D=5，无需反馈通路；32 为偶数，下一轮仍保持 Bank0 起始相位。
这里依赖的是轮转 32 个独立结果地址，而不是单凭输入向量宽度为 32。
不足 32 行或其他访问顺序同样不增加反馈通路，必须由编译器安排足够间隔，
同时满足 Bank 相位。读取必须晚于上一轮写回提交，不能在同 Bank 的
写回沿同时读取。仅有输出、不存储的结果不能作为后续 SRAM 累加的旧值。

内部累加和存储均保持 FP32。DIRECT_OUT/ACC_OUT 的后端指令 out_bf16（默认bit22）
选择 FP32 或 BF16。两种格式通过同一个一级输出模块
`lpu_mxm_output_pipe`，从本列指令发射到结果均为6拍，II=1。
FP32也通过该寄存器，不允许另走零延迟短路径；连续切换输出指令及格式
不会因输出延迟不同而冲突。该级只在输出支路，ACC_STORE 写回为 L6、
读请求至写回 D=5，所有 SRAM 数据仍为 FP32。

BF16使用RNE，保留符号零和非正规数，不启用输出FTZ；可舍入进位到下一
指数，有限数溢出为对应符号的Inf。Inf保持，NaN保留符号和高位payload并
置quiet位，低位payload非零的NaN也不能变成Inf。FP32直通保持全部原始位。
输出接口仍为每lane32bit：FP32模式占全部32位，BF16模式低16位有效、
高16位为零，`result_bf16_o` 标明每列当前批次的格式，地址/标签同步。
这只是核心数据承载接口；输出目的地选择及最终stream打包暂缓。
独立后端指令默认23位，布局见 [mxm_instructions.md](mxm_instructions.md)。
地址宽度由逻辑深度推导，默认1024个地址使用10位，包含Bank选择最低位；
每个Bank仍为512×256bit。COUNT采用10位COUNT−1编码，实际为1～1024批。
四种操作均检查base+COUNT不超过逻辑深度，DIRECT_OUT地址仅作结果批次标识。
FIFO、传播寄存器及地址流水元数据按实际位宽保存；公开地址监测口补零到16位。
复位不清空 SRAM 数据阵列，只清除初始化有效位与流水状态，必须先写后读。
run=0 取消在途操作但保留已存储数据及初始化状态；重新开始需要编译器
重新安排被取消的指令。未来宏替换必须保持已验证的服务沿和返回延迟。
