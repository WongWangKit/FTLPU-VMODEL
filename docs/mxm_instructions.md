# 新版 MXM 指令与控制流

2026-11-10 修订：无COUNT指令；新增配对参数双Buffer、参数加载队列与反量化执行队列。
编译器、数据供应方和RTL共同遵守的规则见
[时序与输入调度约定](mxm_scheduling_contract.md)。

## 实现边界

`lpu_mxm_core` 连接五条独立指令队列、INT8入口反量化、BF16 Supercell阵列、向下/向左结果回传、
FP32累加器、两个单端口Bank及可选BF16输出。旧 `lpu_top` 仍使用legacy路径，
没有迁移新版指令及最终stream打包/输出目的地。

计算和后端每次有效launch各发射一拍操作，不再把一条指令展开成多批。
连续计算由编译器逐拍发射；相同指令内容也必须以独立有效发射表示。
没有launch的周期是空拍，寄存器保留的字不会自动重复执行。
最少32批连续计算、隐藏换权重延迟及偶数地址轮转仍是编译器约定，未取消。

## 指令编码

### 计算队列：7位

定义见 `rtl/mxm/lpu_mxm_isa_pkg.sv` 的 `compute_instruction_t`。

| 位域 | 字段 | 含义 |
|---|---|---|
| 6:1 | activation_stream | 6位行内activation输入流编号 |
| 0 | weight_buffer | 使用Buffer 0或1 |

队列身份已表示计算，不含操作码、版本位、保留位或COUNT。128种二值编码均有定义。
例如流5、Buffer0为 `(5<<1)|0 = 0x0a`。长度不受旧10位数量字段限制。
每条有效操作由独立16位事务标签标记，标签随指令一起延迟，每次接受发射加1并回绕。
标签不表示指令内索引，不参与执行结束或最小粒度判断。
原 `compute_row_index_o` 已删除，公开监测口改为 `compute_row_tag_o`。

### 权重加载队列：2位

| 位域 | 字段 | 含义 |
|---|---|---|
| 1 | weight_buffer | 写入Buffer 0或1 |
| 0 | column_mode | 0=MATRIX，1=COLUMN |

权重及scale/zero的Stream编号固定在配置中，删除旧weight_stream字段，4种编码均有定义。
每Lane默认Stream0读INT8，Stream1/2拼BF16 scale，Stream3读INT8 zero。
入口反量化只发生一次，D1减零点、D2乘尾数并检测移位量、D3归一化/RNE后直接写入原BF16权重寄存器；
D3不另加输出寄存器。参数先成对加载到参数双Buffer，D1读出实际值后随数据传递；没有参数SRAM或参数地址字段。
详见 [入口反量化与流水划分](mxm_weight_ingress.md)。
MATRIX仍固定接收MATRIX_N拍INT8（默认32），COLUMN固定一拍，两者共用BF16移位链。
固定模式加载的剩余拍数、移位索引保留，与已删除的计算可编程重复次数不同。
MATRIX最后INT8输入拍可接收下一条加载；COLUMN允许逐拍发射。
从加载指令本地生效到首个BF16写入为3拍，而不是输入数量额外增加3拍。

### 参数加载队列：1位

`param_load_instruction_t`仅含bit0 `param_buffer`，选择参数Buffer 0/1。
每次launch从固定Stream1/2/3原子接收一行CELL_K对BF16 scale、INT8 zero，关闭zero时不读Stream3。
不要求权重Stream0有效；不含COUNT、参数地址或源Stream编号。
参数编号独立于BF16权重Buffer编号，默认整MXM两套参数寄存器合计1536bit。

### 反量化执行队列：1位

`dequant_instruction_t`仅含bit0 `param_buffer`，为当前权重输入拍选择参数组。
一条MATRIX加载必须配MATRIX_N条逐拍反量化指令；COLUMN配一条。选择可重复或逐拍切换，
不把参数选择固定在整个MATRIX内，也不自动重复队首。
D1同时读取配对zero/scale，zero用于减法，scale拆解值锁存到后续流水。
参数Buffer编号在D1后结束使用，目标权重Buffer编号和valid继续推进到D3。
未初始化参数读取、权重/执行拍不匹配、同沿读取并覆盖同一参数组均置fault，无自动停顿。
另一组可同沿加载；同一组在D1采样后的下一沿即可更新。

### 后端队列：默认13位

定义见 `rtl/mxm/lpu_mxm_backend_isa_pkg.sv` 的 `backend_instruction_t`。

| 位域 | 字段 | 含义 |
|---|---|---|
| 12 | out_bf16 | 仅输出类操作允许置1 |
| 11:2 | address | 当前这一批的逻辑地址，默认10位 |
| 1:0 | opcode | 00=DIRECT_OUT，01=STORE，10=ACC_STORE，11=ACC_OUT |

不含COUNT、版本位或保留位。地址位宽 `A=max(1,$clog2(DEPTH))`，总宽度为 `A+3`。
一般布局为 `out_bf16[A+2] / address[A+1:2] / opcode[1:0]`。
每拍由编译器直接提供实际地址，不再保存base_address、不再生成批次index，
也不再使用base+index加法器。默认深度1024映射到两个512×256bit Bank：
最低地址位选择Bank，余下9位选择Bank内位置。
四种操作统一检查address<DEPTH；非2的幂深度的多余编码被拒绝。
DIRECT_OUT的地址是结果批次标识，不是最终输出目的地。
STORE/ACC_STORE的out_bf16必须为0，违规置fault。

示例：地址17、ACC_OUT、BF16输出为 `(1<<12)|(17<<2)|3 = 0x1047`。
若连续访问0～31，编译器发射32个地址分别为0～31的操作，而非一条长度32的操作。
同一行其他输出位置复用延迟后的同一指令序列，不分别携带地址流。
公开地址监测口仍补零至16位，内部地址元数据按实际A位保存。

默认深度16时，五条FIFO的指令数据位为 `16×(7+2+1+1+13)=384bit`；
这是指令payload，不包含指针、valid和控制，也不代表整体面积或功耗比例。
旧17/8/23位及7/8/13位格式与新7/2/13位格式不兼容，禁止靠截断转换。

## 固定延迟的指令传播

`lpu_mxm_instruction_wave` 不再保存duration、remaining、批次index、pending或传播年龄。
每拍推进指令和发射有效位；有效位为0传播空拍，指令内容相同仍能连续更新。

```text
SL0本地寄存器 → 中继1 → 中继2 → SL1本地寄存器
      E0          E1       E2           E3
```

两级中继加接收端本地寄存器构成相邻Superlane三拍延迟；不是只延迟两拍。
前端计算、权重加载、参数加载和反量化执行各自使用独立流水，均每拍可传递一条，II=1。
加载的模式执行占用由独立固定加载器检查，不会阻塞计算传播。
后端仍每相邻Superlane一拍，匹配回传结果的相位，使用同一模块的INTERVAL=1。

## 入队、发射与有效位

五条队列各有enqueue valid/ready和显式launch。入队不等于执行。
队首必须在launch前存在；同沿往空队列写入不能立即发射它。
满队列同拍出队和入队可复用槽位，深度1也支持连续发射。
计算、参数加载、反量化执行和后端launch_ready由run和队首存在决定，没有可编程长度或传播占用限制。
加载另外检查固定模式是否已到可替换边界。
空队列发射、加载过早替换、输入缺失、参数未初始化/同组读写、权重/反量化拍不配对、数据标签错位、
尚未提交地址重访和实际Bank冲突均继续置sticky fault；不自动停顿或重试。
没有硬件最少32批检查，也没有“指令字段为奇数”的检查；编译器负责这些调度条件。

run=0取消在途指令及数据valid、清fault与标签分配器，保留队列、参数值及其初始化状态和SRAM已存内容。
复位清队列及有效/初始化状态；不逐项清除SRAM数据。恢复时需重新安排完整依赖。

## 阵列、后端与输出时序

算术流水、权重链、结果回传、累加器数据通路和Bank结构不变。
以底层一拍计算在S沿发射，默认四层、列号c从左起、行号r从底起：

| 事件 | 时刻 |
|---|---|
| 行r指令寄存器有效 | S+3r沿后 |
| 单元(r,c)采样activation | S+3r+1+c |
| 顶部列c结果可用 | S+21+c沿后 |
| 左端Superlane c回传结果可用 | S+25+c沿后 |
| 对应后端指令发射 | S+23 |
| 最终输出/写回 | S+29+c |

从A/B会合采样沿T倒推：后端launch=T−3，SRAM读=T−2，A/B在T−1沿后可用，
A1/A2/A3为T/T+1/T+2，写回或输出为T+3。新部分和直接进入A1，无额外宽等待寄存器。
四种操作的后端launch到输出/写回均为6拍；读到写回D=5。
FP32/BF16输出共用一级寄存器，BF16采用RNE、不FTZ，低16位承载结果，高16位清零。

实测32批主场景：参数预取E−1/31/63/95，权重加载E0/32/64/96，每个权重输入拍配一条反量化指令；计算每拍发射E34～161，
在E34/66/98/130切换四组32批的Buffer；后端每拍发射E57～184，
STORE/ACC_STORE/ACC_OUT/DIRECT_OUT分别从E57/89/121/153开始。
顶部四列首批E55/56/57/58，左端回传E59/60/61/62，首批最终输出E127/128/129/130。
这些是连续发射区间，不是四条自动重复的指令。

## 验证与证据

运行 `python scripts/test_mxm_supercell.py`；生成报告使用
`python scripts/plot_mxm_timing.py --simulate`。本地报告在
`output/instruction_supercell_array_test_results/index.html`，CSV/VCD采自公开端口，
日志及SHA256记录对应测试和源码；生成报告/波形不作为源码提交。

验证包括：128种计算字和4种加载字；66048拍计算及264192次逐行检查、标签回绕；
多种行数/队列深度的连续相同指令、空拍、复位/run取消；MATRIX固定32拍及连续COLUMN；
后端全部16种操作交接、576拍数据与17拍混合格式无空拍输出；
深度2/6/1000/1024/2048/65536的全部原始后端编码和末地址读写；
完整阵列和后端的32/40/1024批连续换权重；33批冲突负例和34批合法轮转。
测试中的批次数是编译器刺激参数，不是恢复COUNT指令或RTL循环。
物理SRAM宏、布线时序、最终输出目的地/stream格式和真实编译器尚未接入验证。
新增验证包括参数加载/执行队列的独立发射与3拍传播，参数复用、D1后覆盖、独立参数/权重编号，
以及缺/多反量化拍、参数未初始化、同组读写和新队列空发射；详见 [入口反量化](mxm_weight_ingress.md)。
