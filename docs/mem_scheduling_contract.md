# MEM 指令传播与编译器时序约定

修订：0.4。日期：2026-11-11。

本文件约定新版 `rtl/mem_native` 已实现的逐指令 1/3 拍传播、模式切换调度和有效位语义。
编译器须遵守本文件；RTL 不自动插入模式切换空拍。
本文件不表示整条 MEM → SRF/SXM → MXM/VXM 通路已经完成对齐验证。
完整 native 指令定义见 [mem_instructions.md](mem_instructions.md)。
MXM 侧约定见 [mxm_scheduling_contract.md](mxm_scheduling_contract.md)。

## 1. 指令粒度与传播方向

- 每条独立 MEM 指令流从最下方 SL0 向上传递，最上方为 SL(S−1)。
  当前每个逻辑 Bank 有独立指令入口与纵向流水；入口不等于 MEM 内部另有 FIFO。
- 每个有效指令槽在本地执行一次，占一拍。同一条指令在不同 Superlane 各执行一次。
  相同指令字连续有效出现，表示多个独立操作，不以指令内容变化或 valid 上升沿触发执行。
- 层间延迟可选 1 拍或 3 拍；3 拍模式在现有一级寄存器基础上增加两级。
  延迟级保存完整指令、valid 及实现所需的模式信息，不使用 COUNT 重复展开指令。
- 两种模式均须支持填满流水后每拍传递一条指令。3 拍传播不表示本地执行三拍，
  也不表示每三拍才能发射一条。

| 模式 | 相邻 Superlane 的指令执行间隔 | 用途约定 |
|---|---:|---|
| 短路径 | 1 拍 | 面向 VXM 的供数相位 |
| 长路径 | 3 拍 | 面向 MXM 前端的供数相位 |

模式按独立指令流调度，由每条指令携带的模式位指定。MEM 不根据方向或 Stream 编号
自动判断下游消费者，也不使用一个立即影响全部在途指令的全局模式位。

### 指令编码

复用 native 32 位指令当前的保留位 `[30]`，命名为 `delay3`，不增加指令字长度：

| 位域 | 定义 |
|---|---|
| `[30]=0` | 相邻 Superlane 之间传播 1 拍 |
| `[30]=1` | 相邻 Superlane 之间传播 3 拍 |

其他位域保持原定义：`[31] preserve`、`[29:15] row`、`[14:9] reserved=0`、
`[8] direction`、`[7:3] stream_index`、`[2:0] opcode`。
`valid` 仍为随指令传递的独立有效位，不编码进指令，也不增加 COUNT。
模式位随完整指令经过中继，每个交界处按该指令的模式转交；本地 Read/Write 语义保持不变。

入口合法性检查、传播路径与相关验证参考模型已按该编码调整。
现有旧 47 位 VMODEL 适配器保持短模式映射；若要从该接口选择长模式，须另行定义来源。
旧 47 位指令的 `[30]` 属于地址位，不能直接重解释为 native 的 `delay3`。
参数化原始 32 位入口已同步支持 `delay3` 的合法性检查与透传，适配器无额外寄存器或延迟。
该入口默认使用扩展格式；冻结 C7 编码验证显式选择 `P_ALLOW_DELAY3=0`，详见指令定义文件。

## 2. 周期定义与编译器职责

`E_t` 表示本地执行指令的时钟上升沿。设：

- `S`：Superlane 数量，`r=0..S−1` 从下向上编号；
- `T_i`：指令 i 在 SL0 的执行周期；
- `d_i`：指令 i 在每个交界处采用的传播延迟，取 1 或 3。

在没有停顿且各交界处保持该指令模式的条件下：

```text
指令 i 在 SLr 执行的周期：t_i(r) = T_i + r × d_i
```

编译器负责逐拍发射、插入空拍、安排模式切换，以及协调数据供应、访存依赖和端口冲突。
空拍用 `issue_valid=0` 表达，完整有效指令不得靠后续硬件计数器自动补发。
硬件负责确定延迟的传递、有效位管理，以及每个本地槽位的单次执行。

模式切换时，旧指令保持旧传播延迟，新指令采用新传播延迟。
旧、新模式可以同时存在于同一纵向链的不同位置；实现须使用随指令保存的模式信息，
或与该时序等价的逐交界处切换控制。不能无条件在同一拍切换整列所有出口。

## 3. 模式切换的最小发射间隔

设旧模式最后一条指令在 SL0 的执行周期为 `T_old`，新模式第一条为 `T_new`。
为了保证每个 Superlane 上旧指令执行完毕后，新指令最早在下一拍执行，须满足：

```text
对所有 r：T_new + r × d_new >= T_old + r × d_old + 1

T_new_min = T_old + 1 + max(0, (S−1) × (d_old−d_new))
底层最少空拍数 = T_new_min − T_old − 1
               = max(0, (S−1) × (d_old−d_new))
```

这里的空拍只解决同一条纵向指令流的追赶与顺序问题；SRAM 地址依赖、SR 注入/消费冲突、
下游计算及格式转换等其他约束仍须分别满足，可能要求更大的间隔。

### 3 → 1 拍：从最上层连续执行倒推

默认 `S=4`，旧指令在 SL0 的最后一次执行为 E0，则底层插入 E1～E6 共 6 个空拍，
新指令从 E7 开始。最上层旧指令 E9 执行，新指令 E10 执行，两者紧邻。

| 位置 | 旧模式最后一条指令 | 新模式第一条指令 | 中间空拍数 |
|---|---:|---:|---:|
| SL0，最下方 | E0 | E7 | 6 |
| SL1 | E3 | E8 | 4 |
| SL2 | E6 | E9 | 2 |
| SL3，最上方 | E9 | E10 | 0 |

底层可以在 E7 开始新模式，上层继续完成旧模式的在途指令。
各层间的空隙逐步收紧；不要求底层一直等待到旧指令在最上层执行完毕后才开始发射。

### 1 → 3 拍：底层可以连续交接

仅考虑指令顺序时，底层无需额外空拍。旧指令 SL0 最后执行 E0，新指令 SL0 首次执行 E1：

| 位置 | 旧模式最后一条指令 | 新模式第一条指令 | 中间空拍数 |
|---|---:|---:|---:|
| SL0，最下方 | E0 | E1 | 0 |
| SL1 | E1 | E4 | 2 |
| SL2 | E2 | E7 | 4 |
| SL3，最上方 | E3 | E10 | 6 |

后续指令传播变慢，空隙逐层扩大。切换时仍须满足下一节的有效位规则，
不能把长路径中已交付指令的残留副本重新作为有效指令输出。

## 4. valid：执行、传递与槽位释放

`valid` 与完整指令同步保存。`valid=0` 时，不得触发本地读写或其他指令副作用，
寄存器中的指令比特可以保留旧值。

“拿去执行后将 valid 清零”指释放当前槽位，须遵守以下规则：

1. 本地执行和向上传递是两个动作。同一条指令在本地执行后仍需到达上一层时，
   下一流水级须接收该指令及其有效位。可以在同一沿完成旧值采样和本地槽位释放，
   不能因清除本地 valid 而取消向上传递。
2. 当前槽位执行或转交完毕，且没有新指令装入时，下一拍 valid 为 0。
   每个已占用的中继槽位也应在转交后释放，不能持续输出同一个有效副本。
3. 旧指令执行或转交的同拍若装入新指令，下一拍 valid 应为 1，并保存新指令。
   新装入优先于“旧槽位释放”；不能无条件清零。连续多拍 valid=1 可以对应连续不同指令，
   也可以对应连续多条内容相同的指令，每拍都须执行。
4. 三级延迟中的中间级只负责传递，不能提前触发目的 Superlane 的本地执行。
   同一边界的 1 拍出口和 3 拍出口只能交付同一条指令一次；未选择路径的副本须屏蔽或清除，
   模式切换不得让已经交付的副本重新生效。
5. 复位清除所有在途 valid。若实现 busy/empty 状态，必须覆盖全部中继级，
   不能只观察 Superlane 当前执行出口，遗漏长路径中间级里的有效指令。

这些规则保证每条有效指令在每个 Superlane 执行一次，不需要保存历史指令来做内容去重，
也不需要通过 COUNT 维持本地指令的执行持续时间。

## 5. 与数据通路的对齐

设 SLr 从本地 MEM 指令执行到下游采样点的总延迟为 `L_r`，则：

```text
数据到达下游的周期 = T_i + r × d_i + L_r
```

当各 Superlane 路径等长，即 `L_r=L` 时，层间 3 拍传播可提供 MXM 前端所需的 3 拍供数相位。
SL0 的绝对发射时间仍由编译器根据公共延迟 L 倒推。
若存在不等长路由，编译器还须补偿相应差异，不能仅凭 3 拍模式认定整链已经对齐。

`L_r` 应按实际接线包含 SRAM 读响应、SR 注入、后续 SR/SXM 传输及消费者采样边界。
本约定不将这些阶段合并为已验证的固定拍数，也不把本地 SRAM 读延迟改成 3 拍。
Write/WriteTap 同样受纵向指令传播相位影响，编译器须保证对应数据在本地执行时到达。
同一条 MEM 数据流若同时供给两种不同层间相位的消费者，需要独立调度或分支补偿。

## 6. RTL 实现与验证入口

- [mem_bank_control_column.sv](../rtl/mem_native/mem_bank_control_column.sv) 每个交界处保留一个
  执行寄存器，增加两级只接受长模式指令的中继。短指令不向额外两级写入有效副本。
  各级 valid 每拍由新指令或空拍替换，模式取自各自保存的完整指令。
- `pipeline_busy_o` 包含执行出口和全部额外中继级；north trace 仍为独立观察寄存器，
  不延长功能 busy。复位清空在途 valid，不清 SRAM。
- [mem_slice.sv](../rtl/mem_native/mem_slice.sv) 接受 native `[30]`，按每个 Bank 的独立入口传递。
  旧固定延迟参数 `P_MEM_CONTROL_HOP_CYCLES` 已从控制列、逻辑 Bank 包装与调用处移除，
  用指令模式位作为统一的层间延迟来源。
- 仿真在每个交界处检查短指令是否追赶尚未转交的长指令，非法时 `$fatal`。
  该检查不参与综合；硬件没有自动等待、仲裁或重试，合法调度仍由编译器保证。

运行本次验证：

```powershell
python scripts/test_mem_timing.py
```

脚本使用 Icarus Verilog，支持 PATH 或本地 `build/iverilog/bin` 安装。
`build/mem_timing/results.json` 保存结果与源文件摘要；同目录 CSV 为实际 MEM 本地执行事件。
新测试从公开端口检查 2/4/8 层配置下的指令/数据时序、连续发射、相同字连续执行、空拍、
最紧凑切换、非法切换、复位、busy，以及实际 MEM→SRF 各列的数据前沿。
原 1 拍基线还与 Git 修订 `8bcf380` 的旧实现作轨迹比较，并回归原有故障、适配器与 MEM/SRF 测试。
比较基线可用 `--baseline-ref` 指定；不使用随提交变化的 HEAD 作为固定旧实现。
Icarus 不执行 bind 模块，保留测试台自身的端口断言；这些绑定检查不计入动态验证结果。
完整 MEM/SRF/SXM/MXM/VXM 互连及编译器生成的整链任务仍需后续验证。

此前内部入口的验证不会自动覆盖原始指令适配。补充运行
`python scripts/test_mem_parameterized_ingress.py`，从原始参数化指令验证完整入口链，
结果另存于 `build/mem_parameterized_ingress/results.json`。
